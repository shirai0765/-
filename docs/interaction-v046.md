# 0.4.6：操作の入口と、短い週末結果

開発中・未公開の記録です。現在の公開版は0.4.5です。確認時点の全体266テスト・ビルドと、描画を差し替えた実AppのDOM14カテゴリが成功しました。実3Dと0.4.6の公開検証は未完了で、GPUの指摘による追加修正もあり得ます。0.4.5の合格や以下の単体確認を、今回の実3D・公開確認へ転用しません。

## 街を動かす操作と、店へ入る操作

通常は「俯瞰で経営」です。ゲーム街とApp内の実測街の両方で、ドラッグ・一指操作は平行移動、ホイール・二指操作は拡大縮小へ割り当て、角度を固定します。地図メニューから「街を眺める」を選んだ場合だけ回転できます。「俯瞰で経営に戻る」は現在の中心と距離を保って経営用の角度へ戻します。

区画を選ぶ操作と開業は、施設ダイアログを開閉する操作にしました。店へカメラを自動移動しません。店舗管理・週報の「街でこの店を見る」から明示的に近景へ進み、「街全体に戻る」で俯瞰へ戻ります。実測未対応の店舗は同じ会社・同じ区画を保ってゲーム街へ移ります。開業・地図切替・店舗近景の操作を、実測建物にカフェの外観を配置した実装とは扱いません。

ゲーム街の営業店舗・保有物件の目印は44px相当とし、「自社」を表示します。候補は34px相当です。これは描画上の設定値で、全端末の指操作の実測結果ではありません。街の経営用角度を維持したまま、目印または一覧から施設操作へ入れる構成です。

native dialogを開いている間とタブ非表示中は、両街の描画ループとカメラ操作を止めます。ゲーム街の歩行表現の時計も停止時間を除外し、再開時に時間の空白を一気に進めません。近景の人影は直近の決算客数から作る最大8体の印象表現で、現時点の来客・行列や将来予測ではありません。週の進行や保存値はこの描画で変更しません。

## 指摘から変えたこと

「触ってもどんな変化があるかわからない」「週報が長く、一目で見られない」「数字が突然出るだけ」という指摘を受け、店舗の操作と決算結果を整理しています。街を全画面にし、必要時だけパネルを開く構成は維持します。

店舗管理は、直近の実績から「商品・価格」「人員・店長」「広告・改装」「営業実績」の目的別入口へ分けます。選んだ操作だけを表示し、未決算の新店は利益0円の実績として見せません。設定を入力したことと、営業後に得られる実績を区別します。`StoreManagementPanel` のコード読取と実Appの描画差替え検査の範囲は、以下の確認記録を参照してください。

通常の週末結果は `WeeklyResults` に分離しました。最初の画面は次の情報に絞ります。

1. 黒字・赤字を明示した大きな全社純利益。初回表示では約650msで確定値まで変化します。
2. この決算の現金増減と、決算後の手元資金。
3. 当週の来店者数と、街へ戻る・次の出店候補を見る操作。

店舗ごとの利益・来店者数・満足度、同店を調整する入口、出店時の比較、全社収支と出来事は初期状態で閉じた詳細へ移しました。初決算の記録を主画面へ重ねて長くしません。次の出店は任意で、黒字を理由に出店を強制・推奨したり、新しい現金報酬を作ったりしません。

通常週報は明示的な `onBrowseSites` で候補一覧を開きます。過去の出店記録・連続営業で使う `OpeningResults` にも同じ任意callbackを追加しました。Appへ接続済みで、「次の出店候補を見る」は一覧を開きます。経営メニューの「直近の営業結果」から確定済みの週報を再閲覧できます。

## 初回ガイド、現金、音楽

初めて会社を開いたときは、出店→店舗設定→週終了の3段階を示す短いガイドを表示します。読了は会社の保存データと別のブラウザー設定へ記録し、経営メニューの「遊び方」から再表示できます。店長は人員・広告の配分枠内で価格・人員・品質・広告を調整し、出店や改装はプレイヤーが選ぶことも説明します。

街のHUDは「手元資金」を明記し、1億円未満は円の金額を表示します。ダイアログを読んでいる間は通知を自動消去しません。利益と現金は別の値として週報へ表示し、成長戦略の見込み幅と借入・資金不足の危険は既存の `getWeekOutlook` から取得する方針です。

「音楽」から再生を押すと、Web Audioによるオリジナル8小節の街BGMを開始します。自動再生はせず、再生・一時停止・消音・音量を選べます。音量と消音だけを会社保存と別に記憶し、ページを開き直した際の再生は再び手動です。非表示タブでは一時停止します。外部音源の取得はありません。今回のコード読取は音の聴感・実端末の再生確認ではありません。

## 数字と演出の境界

表示は保存済みの `lastReport` と `history` だけを使い、予測や決算を再計算しません。「決算後の手元資金」は報告週と一致するhistoryから取得します。決算後に開業・借入を行った現在の現金へ置き換えず、記録がなければ「記録なし」とします。

会社利益の前週差は、正確に前週のhistoryがある場合だけ表示します。過去の店別設定・週次実績は保存されていないため、店舗ごとの前週差や「値上げによって利益が増えた」といった因果は作りません。客足が同じでも単価・費用で利益が変わり、広告や品質の判断も店舗の処理能力等に依存します。一回の決算差を操作の効果と断定しません。

演出は表示用の数値だけを変えます。`prefers-reduced-motion` では即時表示し、同じ会社・同じ週の再閲覧はセッション内で再演出しません。途中で閉じれば描画予約を解除します。演出の途中でも会計・保存値は確定済みで、閉じる操作で再抽選しません。赤字は文言・負号・赤色で示します。現在の金額形式は `¥-42,300` のような通貨記号の後ろの負号です。

利益係数や終了条件を変える更新ではありません。独立した赤字・回復確認では、初期標準店32区画の見込み赤字が12区画、通常操作の38決算と18回復経路の保存往復一致を確認しました。店長による黒字保証も利益のゼロ丸めもありません。これは現行の赤字と回復が成立する証拠で、UIの分かりにくさを人間のプレイで確定した結果ではありません。研究は `/workspace/shared/shibuya-artifacts/research-v046/loss-recovery-review.md` にあり、係数や保存を変更していません。
