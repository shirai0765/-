# 0.4.2 店舗運営の診断 — DOM 検証

2026-10-06。対象は店舗設定と読み取り専用の運営予測。Chromium の実 DOM 操作を使い、都市コンポーネント `CityView` は明示的に空表示へ置換し、GPU を無効にした。都市描画・Windows 実機性能・初見ユーザーの理解や面白さの検証ではない。

実行スクリプトは [smoke-store-insight-v042.py](../scripts/smoke-store-insight-v042.py)。成果物は `/workspace/shared/shibuya-artifacts/store-insight-0.4.2/`。既存の 0.4.1 の検証・配布成果物は上書きしていない。

## 変更前の独立基準

API 実装前の 0.4.1 エンジンから、公開 action で作成した 29 状態の予測・店長案・週決算・保存内容を取得した。さらに DOM 担当が、同じ旧エンジン上で実際に価格・人数・品質・広告・店長チェックを操作し、各保存 state と予測、週決算、再読込を別途取得した。現金や週数を直接注入した基準ではない。

新画面の数値は旧予測と照合し、操作・保存の全 state を比較する。新 API 自身との照合だけで経済不変と判断していない。29 状態すべてのエンジン独立検査は [設計書の経済検証](design/store-insight.md) と [API 検証記録](store-insight-api-verification.json) を参照。DOM はその代表ケースを使用する。

## 実行結果

11 カテゴリすべて成功。`results.json` に検査結果、基準ハッシュ、画面寸法、非ゼロの円丸め例を保存した。JavaScript / console エラーは 0 件。

| 確認 | 実行内容と結果 |
|---|---|
| 初期状態・読み取り | 初店の利益 53,528 円、需要・上限・客数・満足が旧予測と一致。詳細の開閉前後も保存 state は同一 |
| 実操作 | 価格 950 円 → 人数 6 → 品質 85 → 広告 0 → 店長委任を順に操作。6 時点すべて旧 state・予測と完全一致。入力は既存フォーム操作を使い、品質はキーボード操作 |
| 週進行・実績 | 実際に週を進め、旧版で取得した次週 state と完全一致。前週実績と第 2 週の予測を区別し、再読込後も同じ内容 |
| 品質の条件差 | 満席設定で品質 85 → 100 を操作。客数 1,120 人のまま、利益は 402,440 → 383,120 円、満足は 79 → 84。変更時の現金は減らず、運転費の予測が変化 |
| 店長 | 入力欄を残して実効価格・人数・品質・広告を別表示。通常の調整案と、低満足の元設定を維持するケースを照合。別の店長費も一致 |
| 需要・制約 | 余力がある店、満席の店、人員上限超過、4 店自主管理、1 店委任後の他店への影響を確認。店長の店へ自主管理減の説明を出さない |
| 利益と満足 | 利益 918,175 円・満足 47 の例でも、満足の数値は詳細を閉じた状態で表示される |
| 所有物件・費用 | 店舗の家賃は 0 円。全社の物件維持費が別に残る説明を確認。店舗利益と全社利益を同額にしない。費用 7 項目と明示された丸め調整の和が店舗費用合計に一致 |
| 全社の危険・終了 | 借入中の赤字は既存週末確認に倒産警告を表示。実決算後の終了 state は旧版と完全一致。終了会社に新たな今週予測を出さない |
| 選択・閉店 | 複数店舗の内訳は独立。店の表示先を変えても店名・ID が一致し、別店の開いた内訳を持ち越さない。実際の閉店後は古い予測を除去し、既存閉店 action と保存 state が一致 |

費用の端数例では `表示の丸め調整` の -1 円を DOM 上でも確認している。調整を省いて一致とした検査ではない。詳細を閉じたままでも、制約文・満足・人員上限超過・店長案は表示される。

## 表示の観察と限界

保存された画像は `manager-desktop.png`、`demand-limited-desktop.png`、`normal-mobile.png`、`long-name-mobile-{daylight,metro,night}.png`、`costs-mobile.png`。390px では通常の 7 字名が 379px、29 字名が 415px の診断カードとなった。3 テーマとも横はみ出しはない。高さは `results.json` の `layouts` に記録した。縦スクロールは必要だが、長い店名は折り返され、利益・制約・満足・設定欄が重ならない。

画面の価格は現実の市況ではなくゲーム内の計算であり、表示は今週の入力に対する予測。自動検証では、プレイヤーがその理由を理解したこと、最善の設定を選べること、将来の利益を保証できることまでは主張しない。都市描画は別担当の実 GPU 記録で検証する。

再実行には開発サーバーと Python Playwright / Chromium が必要。基準ファイルは上記成果物フォルダーへ保存済み。

```sh
python3 scripts/smoke-store-insight-v042.py
```

別の出力先を使う場合は `STORE_INSIGHT_OUT` を指定し、基準ファイルの場所を `STORE_INSIGHT_BASELINE` と `STORE_CONTROLS_BASELINE` で明示する。
