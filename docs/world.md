# 渋谷ワールドのデータと制作範囲

現在の `src/data/district.ts` は、経営シミュレーションと3D表示を接続するための**手作業で構成した渋谷風の仮マップ**です。実測地図、実在建物のフットプリント、PLATEAU の3Dモデルはまだ取り込んでいません。道路を簡略化しており、実在の渋谷を忠実に再現した成果物として扱うことはできません。建築物の名称・経済数値もゲーム用です。

ユーザーの目標は実在する渋谷の地理と建築を使うことです。この仮マップは経営検証の土台であり、その目標を満たす最終マップではありません。

## 座標と描画用の予約領域

原点はスクランブル交差点、東が +x、南が +z。数値の単位はゲーム空間のメートルで、現実の距離は圧縮しています。範囲はおおむね -200～200m。背景建物と店舗区画は道路・鉄道と相互に重ならないよう配置しています。

| 建物・施設 | 中心 x,z | 予約幅×奥行 |
| --- | --- | --- |
| スクランブル交差点 | 0,0 | 50×50 |
| 渋谷駅 | 75,42 | 38×70 |
| スカイタワー | 124,43 | 46×52 |
| SHIBUYA 108 | -43,-34 | 40×42 |
| ミヤシタ・ガーデン | 116,-143 | 62×78 |
| 南北の鉄道 | 75,0 | 16×410 |

建物の予約領域は描画での上限目安です。仮マップの座標を緯度経度として利用しないでください。

## 経営データ

- 4地区各8件、計32件の出店候補。背景建物は取引対象外です。
- `footfall` は1週間の通行量、`rent` は1週間の家賃です。月額ではありません。
- `purchasePrice` と買収価格は円単位のゲーム用評価額です。実在の土地・企業の評価ではありません。
- 地区ごとに人流・所得傾向・家賃を変えています。駅前は高い固定費、裏通りは少ない人流、高所得街区は品質投資との組み合わせを判断します。
- 買収先8社は飲食、不動産、鉄道へ進みます。`weeklyProfit` はシミュレーション前の想定営業利益、`risk` は変動に使う0～1の係数です。確定利回りでも年間倒産確率でもありません。
- 背景建物の集合は決定的に生成されます。同じ版のゲームで起動するたびに変わりません。

## 実在データへ置き換える手順

1. 正式な配信カタログから東京都渋谷区の建築・道路・地形を選び、データ年度と範囲を固定する。
2. CityGML/3D Tiles の座標参照系と高さ基準を読み、原点・縮尺・軸方向を統一する。
3. 渋谷駅・スクランブル交差点・109・宮下公園の位置を地理データで確認する。実在する建物の外形を保持し、店舗区画と所有権のゲーム情報を別レイヤーで関連付ける。
4. 出典、ライセンス、元データURL、取得日、加工内容を保存する。建物形状と写真・テクスチャの権利条件はそれぞれ確認する。
5. カメラ範囲で読み込むタイルを絞り、軽量LODと詳細LODを切り替える。経営上の全物件を常時高精細描画しない。
6. 実際の3Dデータを表示してから、仮マップの代替が完了したと判断する。ダウンロード先の発見だけでは完了にしない。

実在地形への置換で物件の位置やIDが変わる場合、既存セーブを維持するには対応表による移行が必要です。現時点では互換性を保証していません。
