# Blender-finished assets in the game

`LoadedAssetPool` in `src/city/loadedAsset.ts` belongs to one `CityView` scene. Its public URLs are `./models/authored/108-polished.glb` and `./models/authored/cafe-polished.glb`. The first must contain the game's fictional **108** identity, including digit geometry and image textures. The café must omit its static horizontal wordmark so the separately drawn player-owned business name remains visible at y = 3.47 m. Both GLBs use the procedural originals' pavement origin, metres, Y-up and +Z frontage.

`pool.mount(url, fallback, active = true)` returns `{ group, setActive(active), release() }`. Add the returned stable group to the scene. The fallback must exclusively own its geometry/materials/textures. Its position, rotation and scale move onto the stable group; this preserves lot-specific café width without scaling twice. The procedural model appears immediately. A successful GLB load replaces only the group's contents, disposing the exclusive fallback once. A failed fetch or parse leaves the fallback and a diagnostic `assetLoadError` in group.userData, with no repeated retry or user alert. `assetStatus` is `fallback`, `loading`, `loaded` or `released`.

A URL is fetched and parsed once per scene. Its clones share immutable geometry, materials and textures. **Call `pool.release(handle)` before independently disposing a slot or any parent that contains its borrowed clone.** Release detaches the clone without disposing the cached resources, so sibling stores continue to work. The template cache lasts until the scene ends. Sharing buffers reduces memory and parsing cost; each visible storefront still adds draw calls.

`setActive(false)` hides the slot and invalidates pending attachment to a closed or restyled store. Reactivation can attach the cached result. The existing game retains storefront groups for the finite list of lots, so closing a store does not create an unbounded cache. Names, economic settings and saves are unchanged. The player's sign is outside the loaded asset and repaints after the local Japanese font finishes loading.

For whole-scene teardown, **call `pool.dispose()` before `disposeScene(scene)`**. This aborts pending fetches, releases every handle, and disposes shared template resources once. A GLTF parse that finishes after teardown is immediately disposed and never attached. `disposeScene` deduplicates geometry, material, texture and ImageBitmap sources before releasing them.

`await waitForLoadedAssets(scene)` settles all started requests and local font readiness. The readiness hook uses a scene-local Symbol.for key outside userData, so Vite HMR and separately imported debug modules still wait for the same pool. Use it before screenshots and GLB exports; `scripts/export-city.py` now does so. Failure settles rather than hanging an export; inspect slot `assetStatus` when a polished model is mandatory. New cafés added after a wait require another wait.

`npx vitest run tests/loadedAsset.test.ts` checks one load shared by two cafés, sibling safety after release, no attachment to inactive/deleted stores, reactivation from cache, abort and late-result disposal across scene teardown, failure fallback without weekly retries, inactive lazy loading, preservation of café placement/width, and one final ImageBitmap.close across shared map/roughness textures, and export readiness across module generations. These lifecycle tests do not substitute for browser inspection of the final Blender models.

## Browser integration verification

`python3 scripts/smoke-loaded-assets.py` verifies the actual public GLBs in the game. Its fixture opens one premium café, then two more through the UI. All three share geometry and materials from one GLB fetch in that scene. The test renames a store, changes its operating style, closes and reopens it, and reconstructs the scene by switching high/low rendering quality. Every saved state is compared against the same actions applied directly to the economic engine; rendering introduces no cash, week or save changes. The fixture's starting cash is test-only.

The completed run passed all scenarios with zero console/page errors. Results and public-model hashes are in `blender-polish/game/loaded-assets-qa.json`; `cafe-polished-in-game.png` shows the imported café at street level and `city-polished-in-game.png` shows the city. Animation was paused in the test harness and screenshots rendered explicitly to avoid continuously rasterizing the city on software GPU. High-quality reconstruction validates geometry/resources without an expensive shadowed frame. Lifecycle/failed-load races are additionally covered by the eight unit tests.

The older `scripts/smoke-architecture.py` and historical `architecture-qa.json` target the procedural fallback revision. Their exact mesh-count assumptions do not describe Blender-imported hierarchies; use this dedicated loaded-assets test for the polished integration.

The integrated street initially contained both the old static pair of pavement tables and the café's own terrace. `CityView` now keeps each original pair in a lot-specific group. Those tables hide when that lot has a detailed premium café (excluding the shallow `center-03` treatment), or when any store reaches level 2 and supplies its existing expansion terrace. They return after closing or switching to a non-premium level-1 store. Unrelated lots keep their original tables. The final browser run explicitly verifies those visibility transitions in addition to the seven original integration checks. The café PNG now uses a 1.72 m eye height and 60° field of view centred on the entry, rather than the earlier distorted 112° full-frontage view; no city geometry is hidden for the screenshot.
