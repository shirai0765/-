# 投資先から資本比較へ渡す計画メモ

0.4.1。`src/ui/investmentPlanning.ts` は、選んだ出店・共同開発・買収の必要額を財務画面へ渡す読み取り専用ヘルパーです。現在の資金で買えるかを判定する実行許可や、将来の利益を示す見積書ではありません。資金不足や上場条件未達でも計画を考えられますが、実投資は戻り先で現在の条件を確認して別に実行します。

## 金額と支払時点

| 対象 | メモへ渡す `spending` | 含まないもの・支払時点 |
| --- | --- | --- |
| 出店 | 選んだ場所・形態の現在の開業費 | 既存エンジンの開業時支払額。土地の購入は別操作。開業後の利益・維持費・週末現金は戻り先で予測する |
| 駅周辺共同開発 | 選んだ商業／賃貸の着工費 | 週の維持費はこの一括費用に含めない。工事中から実決算に反映。物件・信用・上場の条件をメモで満たした扱いにしない |
| 友好的買収 | 未払調査費と取得時の株式精算、引継ぎ期間すべての準備費を考慮した残り必要現金 | 準備費は将来の週次支払のための確保額で、取得時に一括引落ししない。既に保有している株式の購入代金を二度足さない |

買収の額は公開されている [買収比較](acquisition-strategy.md) の計算を使います。未払調査費を R、現在の買収評価額を Q、選んだ方式の統合費を I、充当する全保有株式の現在時価を H、全準備期間の準備費を P とすると、確保すべき現金は `max(R, R + Q + I - H + P)` です。

- 調査済みなら R は 0。過去の調査費を残り必要現金へもう一度加えません。
- 保有株の時価で取得費を減らし、超過分の返金が準備費を賄う場合も反映します。保有株の購入代金は既払いなので別に足しません。
- 返金は取得時に発生します。未調査なら、将来の返金が十分でも調査費 R を先に持つ必要があり、メモを負にしたり 0 にしたりしません。
- 準備費 P の確保は将来の全社資金繰りの保証ではありません。他事業の損益、借入元本、配当などは別の現金変動です。

財務の「計画支出を差し引いた残額」は、この入力額を使う営業前の単純な差額です。特に買収では準備費の確保を含み、実取得直後の現金残高とは異なります。資金調達の今週予測には、この投資の支出・利益・維持費を適用しません。調達と投資を自動で連続実行する機能はありません。

## 対象が変わったとき

同じ場所にすでに店舗がある、同じ地区ですでに共同開発を着工した、企業が統合中または取得済み、という対象に新しいメモは作れません。共同開発は他方の用途へ切り替えるメモも作れません。

いったん App が保持したメモは概算のまま残ります。週進行や別操作で価格・取得条件が変わっても、編集中のメモを新価格へ自動更新しません。戻り先の画面は対象の現在状態を読み、必要なら取得済みや条件変更を表示し、実行前の予測を作り直します。「計画に必要な現金がある」と「いま投資を実行できる」は別です。

## App での持ち回りと保存の境界

App は `InvestmentIntent`（対象・方式）、その画面を再び開く `InvestmentVisit`、取得時点の `InvestmentMemo`、[資本比較の入力 draft](capital-planning.md) を React の状態として持ち回ります。これらは `GameState` や週末の保存エンベロープに含めません。計画の作成・方式比較・入力・戻るだけでは現金、週、保存済み会社を変更しません。資本調達や投資の実行結果は従来どおり実ゲーム状態に適用し、週末／手動保存の対象となります。

`InvestmentVisit.id` は戻り先を開くための一回ごとの通知です。`InvestmentMemo.id` は会社・投資種別・対象・形態または統合方式から作る安定した識別子で、役割が異なります。

- 同じ会社・同じ対象・同じ方式へ再訪するとメモ ID は変わりません。週や価格が変わっても同じ ID で、財務に戻る際に支出の任意編集や留保額を維持できます。
- 別の場所・企業・地区・方式を選ぶとメモ ID が変わります。資本比較は支出を新しい対象の額へ差し替え、計画メモを有効にします。留保額、借入入力、選んだ調達方法は保持します。
- 会社の新規作成、保存データのインポート、バックアップ復元では、App が投資の文脈・再訪通知・資本 draft をリセットします。別会社の支出や留保を持ち込まないためです。
- ページ再読込で入力メモを復元する契約はありません。通常の保存操作で、編集中のメモまで保存されたとは説明しません。

## 会計レビューと検証

`npx vitest run tests/investment-planning.test.ts --maxWorkers=1`：4 件成功（2026-10-06）。

1. 現金 0 の会社でも 3 形態の出店費を取得でき、同じ状態へ現金だけを与えて実開業した支払額と一致すること。元状態は不変で、資金不足の実開業は拒否されること。同じ対象への再訪・週変化で ID が安定し、別会社・別形態では変わること。
2. 保有株がある買収で、調査前後の差が実際の調査支払に一致し、株式充当後の実取得支払と稼働前に計上される準備費の合計がメモに一致すること。準備費を即時に二重請求しないこと。
3. 大きな保有株の超過返金があっても未払調査の現金を残すこと。調査後のメモが 0 でも、非上場なら上場要件のある企業を取得できないこと。
4. 出店済み区画、着工済み地区の両案、統合中／稼働済み企業の新規メモを拒否すること。条件未達の共同開発を計画しても実行許可を与えないこと。

会計比較用に現金 9 億円・上場・信用 100 を与えた固定 fixture を使っています。現金を 0 にする境界や、取得済み状態を読むために週だけを切り替える境界もあります。通常プレイでの到達性、利益率、初心者の理解、人間の約 30 時間を実証したテストではありません。画面間の draft 復元と警告の見やすさは別のブラウザー検証で扱います。
