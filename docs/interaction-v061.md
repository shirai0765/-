# 0.6.1：週の区切り、カフェの音、銀行の審査

0.6.0をiPhone Safariで遊んだ画面の指摘をもとに、週末の体験と音の入口を改めます。この文書は実装・検証の記録で、公開確定の証拠は末尾へ追記します。

## 営業結果から次の週へ

決算の小さな窓を、街を完全に覆う専用画面へ置き換えました。週の移り変わり、確定した純利益、現金増減、決算後の手元資金を表示し、金額は同じ短い演出で動きます。店舗・費用の詳細は別の表示に分け、最初の結果画面に詰め込みません。次は「街と企業のニュース」、最後は次週の経営へ戻る流れです。途中で街へ戻ることもできます。

表示は保存済みの決算と履歴だけを使います。決算後に物件を買ったり返済しても、過去の決算後現金を現在の残高に置き換えません。同じ結果を開き直すと金額の演出を繰り返さず、動きを減らす設定では最初から確定額を表示します。経営終了時には次週の経営を約束しません。

## その週に確定したニュース

街の需要の変化、全100銘柄の上昇・下落の件数、他社の実際のゲーム内株価の変化を記録します。地区・沿線計画の完成、傘下企業の運営開始は既存の営業モデルが実際に到達した週だけ掲載します。独立した他社の店舗拡張や新製品開発を追加でシミュレーションした機能ではありません。実在企業のリアルタイムニュースでもありません。

決算時に `lastReport.news` へ小さな記録を追加し、表示し直すたびに内容が変わることを防ぎます。ニュースがない旧セーブは、その週に保存した見出しだけを表示します。保存version 1とenvelope 1を維持し、任意フィールドの型・参照・件数・価格変化の整合を読込時に確認します。ニュースを経済計算の入力にせず、株価の乱数・金利・収益・成長条件は変えません。

## ワンタップで音を始める

街の音ボタンから、一度の操作でカフェの環境音とBGMを開始します。音量・BGM・店内音を個別に調整でき、意図して消音・一時停止した状態を尊重します。初回訪問や再読込で勝手に再生はしません。会社のセーブとは別に音量の設定だけを記録します。

音はオリジナルの音楽と、カップ・コーヒー・室内の音を合成したものです。外部の録音や曲を無断転載せず、配布後の外部音源への通信も不要です。Safari向けのコンテキスト作成・再開をユーザー操作の中で開始し、対応する端末ではAudio Sessionをメディア再生として指定します。実際の再生状態、画面を離れたときの停止、割込み・復帰・再試行を扱い、開始できない場合に「再生中」と表示しません。

タッチ入力の実検証で、店舗の目的ボタンを押しても切り替わらない問題を発見しました。入力の確定時にボタンが動くことを防ぐ処理が、タッチのpointerdownまで取り消していたためです。この抑制をマウスに限定し、390pxでタップから価格変更・店舗トップへの移動による編集中入力の確定を確認しました。銀行と店舗のスマホ入力は16pxにし、Safariで入力時に拡大されやすい小さな入力文字を避けます。

## 借りる前に金利と返済を比べる

街の銀行で金額と返済期間を選び、年利、初週の支払額、満期までの利息総額を比較します。金額は候補から選ぶほか直接入力でき、期間は13〜260週。明細は必要時だけ開きます。

「融資審査」で現在の借入枠などを確認し、通過・不通過とその理由を表示します。入力画面から審査結果へ切り替わるため、長い画面の最下部を探し続ける必要はありません。審査後に見出しが固定ヘッダーの裏へ隠れる問題も実画面で発見し、入力・審査・契約の段階が変わると、その見出しが読める位置へ移動するよう修正しました。通過後の明示的な契約ボタンで初めて入金します。希望額や会社の状態が変われば再審査が必要です。審査だけでは借入・返済・週進行・保存を行いません。

金利と借入可否の最終判断は従来の借入アクションと同じです。利息は残高に応じて減り、支払総額は既存借入との合算・毎週の端数処理も考慮した追加額です。追加契約や繰上返済をしない前提を明細に示します。審査通過が営業利益を保証するわけではなく、従来の倒産条件も維持します。

## 検証と公開

証拠の基点は `/workspace/shared/shibuya-artifacts/`。新しい記録は `completion-v061/`、最終の統合結果は `integration-v061/`、公開記録は `deploy-0.6.1/` に置きます。過去の成果物を上書きしません。

実装後の全体テスト、本番ビルド、通常のブラウザーによる決算・ニュース・銀行・音声の検証を実施しました。Linux WebKitはiPhoneのSafari実機とは異なります。実時間の音声信号を測定できても、端末スピーカーでの試聴を行ったとは扱いません。Windows実機と人間の30時間の遊び心地は別途の確認が必要です。

### クラウドでのブラウザー検証環境

通常のPlaywright WebKit 26.5（build 2336）と実アプリのWebGLを使います。Debian 13の不足ライブラリー9パッケージは公式HTTPSのPackages索引・SHAで照合し、ユーザー権限の一時ディレクトリへ展開しました。GTK/WPEの既存ライブラリーを置き換えず、追加ライブラリーだけを各 `sys/lib` から参照します。OS設定・証明書・ブラウザーのセキュリティやRAFは変更しません。

追加パッケージは `libgtk-4-1`、`libgraphene-1.0-0`、`libharfbuzz-icu0`、`libmanette-0.2-0`、`libhyphen0`、`libgles2`、`libcairo-script-interpreter2`、`libhidapi-hidraw0`、`liblzo2-2`。一時cacheは `/tmp/shibuya-public-qa-browsers`、出典・SHAは `/tmp/shibuya-webkit-deps/manifest.json`。これらは配布ゲームの依存物ではありません。

この配置のGLESは実際にロードできますが、Playwrightのシステムディレクトリ検査には見えません。個別のライブラリーロード確認の後、WebKit検査プロセスだけに `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1` を指定しています。これは起動前の依存確認の省略で、ブラウザーのサンドボックスやTLS検証を外す設定ではありません。別環境では通常のPlaywright依存導入を優先し、ライブラリーやGPUがないことをUI不具合と混同しないでください。
