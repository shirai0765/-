## 0.4.1：初決算を先に読む表示への変更

`OpeningResults.tsx` と専用の `opening-results.css` だけで、記録の表示順と導線を変更した。店名の直後に保存済み `OpeningRecord.result` の黒字・赤字・収支均衡、店舗利益、初週来店者数を表示する。次週予測や現在の設定から初決算値を作り直さない。赤字を黒字の祝辞で扱わず、決算済みという理由だけで状態ラベルを緑色にしない。

出店前後の全社利益予測、初決算の全社利益・現金増減、店舗の予測と実績、開業支払は標準で閉じた「出店時の予測・支払いと比べる」にまとめた。出店後の設定・投資、他店・契約の変化で予測との差が出る説明と、開業費を週間利益から再び差し引かない説明を残す。初営業前の閉店・未記録・旧保存にない予測や実績は補完しない。

任意prop `onViewStore?: (lotId: string) => void` を追加し、「店の様子を見る」を既存の運営導線と並べる。表示条件は `closedWeek` がなく、現在の店舗に同じ `storeId` と `lotId` の組が存在すること。明示的な閉店記録、現在見つからない店、同週再出店前の古い閉店記録には近景ボタンを出さない。「この店の運営を見る／この区画を見る」「次の出店候補を見る」「今の運営を続ける」は維持する。近景への移動自体は親画面のcallbackへ渡す。

限定検証ではReactの静的描画を使い、実績が比較より先、detailsが初期状態で閉じる、黒字・0・赤字の文面、閉店・同週再出店・欠落店舗での近景ボタン制限、旧保存の非捏造、描画前後の入力JSON一致を20アサーションで確認した。全テスト・再ビルド・GPU検証はこの変更担当では実行していない。上の0.3.2ブラウザー証跡を0.4.1の近景カメラや改修後レイアウトの確認結果へ読み替えない。親画面の接続と3D近景は統合担当の検証対象。
