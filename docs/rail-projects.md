# 駅周辺共同開発

上場後、鉄道会社を取得する前にも駅と地区への投資を選べる任意の経済機能。共同開発への参加であり、鉄道会社の所有権・子会社利益は増えない。既存8社、市場100件、4地区開発というキャンペーンの取得対象へ追加の必須目標を増やさない。約30時間という所要時間や人間が感じる面白さを検証した機能ではない。

## 条件と二択

上場済み、信用45以上、対象地区に直接保有物件1件以上。各地区で次のうち1計画だけを着工できる。地区はセンター街・道玄坂・宮下／東口・桜丘。

| 計画 | 着工費 | 工期 | 工事中・完成後の維持費 | 完成後の効果 |
| --- | ---: | ---: | ---: | --- |
| 駅前回遊・商業パートナー | 600万円 | 4週 | 6,000円／週 | 地区内の自社店舗需要 +12% |
| 駅近賃貸・生活パートナー | 800万円 | 6週 | 4,000円／週 | 地区内の直接保有・外部賃貸物件の賃料 +16% |

費用はゲーム内の設計値。既存地区開発の第2工程（商業650万円／維持8,000円／需要+9%、賃貸800万円／維持5,000円／賃料+10%）と同じ投資規模を基準にした。共同開発は一度だけの専用用途投資で、既存の開発工程を完了扱いにはしない。実在会社の収益率や観測された企業価値から導いた数字ではない。

商業は店舗に空き能力がある場合に客数・売上へつながる。満席なら需要だけ増え、維持費の分だけ利益が下がる可能性がある。賃貸は外部テナントのいる直接保有物件向けで、自用物件だけなら追加賃料はゼロ。複数の地域物件に効果があるため、店舗の構成と保有物件によって二択の価値が変わる。子会社や市場買収企業の利益には直接加算しない。

効果は既存地区開発と乗算せず加算し、合計で需要+40%・賃料+50%を上限とする。追加分の残枠を共同開発側で計算するため、店舗予測・物件収入へ二重に適用しない。

## 決算と休止

着工時に現金を一度だけ支払う。維持費は着工した今週から毎週の営業利益に含める。工事の終了週 `startWeek + weeks` に入った時点で今週予測へ効果を反映し、その同じ予測が週末決算となる。完成時の追加支払や維持費増額はない。

借入中の利息後利益がゼロ以下なら倒産する既存ルールをそのまま使う。元本返済は利益とは別に週末現金へ反映する。確認画面は着工前後の同じ週の利益・支払後現金・元本返済・週末現金を示し、工事中の費用を含める。完成後の需要効果を先取りした利益予測や自動融資は行わない。

地区の最後の保有物件を売ると、共同開発の効果と維持費は休止する。資金支払済みの工期は経過し、地区物件の再取得時点で工事中なら費用のみ、完成済みなら費用と効果が再開する。再取得時の共同開発費はゼロ。計画変更・中止・返金はなく、その旨を確認画面に明記する。簿価は既存地区開発と同様に着工費の50%で、直接換金する操作はない。

## 状態と接続

`GameState.railProjects` は任意項目。旧セーブには過去の共同開発を補完しない。

```ts
railProjects?: {
  projects: {
    districtId: DistrictId;
    choiceId: 'commerce' | 'rental';
    startWeek: number;
    completeWeek: number;
  }[];
}
```

`startRailProject` 操作で開始する。地区ごと1件、最大4件、定義済みの二択、着工週と工期の整合を保存時にも検証する。完成フラグを別保存せず `week >= completeWeek` で判定するので、読込後・予測中も同じ状態になる。

`src/sim/railProjects.ts` の公開関数:

- `getRailProjects(state)`：4地区の条件、二択、残工期、現在の効果、`available / locked / building / operating / suspended` を返す。
- `getRailProjectEffects(state, districtId)`：当週の追加需要・追加賃料・維持費。工事中は費用のみ。
- `getRailProjectFinancials(state)`：当週の維持費合計と簿価。
- `startRailProject(state, districtId, choiceId)`：検証し、複製した状態へ一度だけ着工費と計画を記録する。
- `railProjectHeadlines(state)`：完成週の決算見出し。

`RailProjectsPanel` は `state / onAction / busy` を受け、実際の `applyAction` と `previewWeek` で確認値を作る。送信処理は同期refで重複クリックを遮断し、状態側も同じ地区の再着工を拒否する。任意の `onShowProject(districtId)` を渡すと、着工済みの地区に「沿線の様子を見る」を表示して都市画面への導線となる。3D表示は公開viewの地区・計画・statusに接続する。

## 検証範囲

`tests/rail-projects.test.ts` は解放条件、支払一度・入力不変性、工事費用、完成週の予測と決算の一致、二択の相互排他、売却・再取得、休止中の工期、自用物件に賃料が生まれないこと、商業の実客数・賃貸の実収入、地区外への効果なし、合算上限、借入利益ちょうどゼロでの倒産、旧セーブ互換・保存往復・不正状態拒否を扱う。

これらは経済を分離した単体fixtureであり、初期資金から到達する週数やユーザーの実プレイ時間の根拠にはしない。通常操作による到達可能性と他の投資との比較はキャンペーン検証、操作と3D表示はブラウザー検証として区別する。

通常操作による別検証は [v4キャンペーン報告](campaign-v4.md) を参照。2シードで商業を21週に着工して25週に稼働でき、賃貸は外部物件取得後の81／105週に着工して87／111週に稼働した。共同開発なし・商業・賃貸の計6経路が既存の全目標へ到達している。早期着工が他の買収を遅らせる場合もあり、商業・賃貸が常に最速の正解になるという結果ではない。鉄道会社自体を早期所有した測定とも区別する。

## 同じ4店舗で変わる判断の具体例

`tests/integration-v4.test.ts` の比較fixtureを、seed765、7週目、地区開発なし・借入なしで計算した。桜丘06・05・02・01に標準店4店を置き、各店の物件を自用保有。品質85、販促0、店長なし。満席側は各店2人／価格580円、空き能力側は各店5人／価格1,200円。外部賃貸ありの行では、さらに桜丘03・04・08を賃貸物件として直接保有する。

全行ともテスト用に資金6億円・上場・信用90を与えて比較しており、通常操作で獲得した資産とは扱わない。着工して7週目まで通常の週次計算を進めた後、同じ状態から共同開発だけを除いた今週予測との差分を取った。表は維持費を差し引いた営業上の効果で、着工費は別払い。完成後の全期間に同じ利益が続くという収益保証ではない。

| 同じ4店舗の運営・保有状況 | 商業の週利益差 | 商業の客数差 | 賃貸の週利益差 | 判断の例 |
| --- | ---: | ---: | ---: | --- |
| 満席、自用物件のみ | −6,000円 | 0人 | −4,000円 | 両方見送り、店舗設定を先に直す |
| 空き能力あり、自用物件のみ | +207,180円 | +240人 | −4,000円 | 商業回遊を比較候補にする |
| 満席、外部賃貸3件あり | −6,000円 | 0人 | +65,126円 | 賃貸設備を比較候補にする |
| 空き能力あり、外部賃貸3件あり | +207,180円 | +240人 | +65,126円 | この配置・価格では商業の利益差が大きい |

最初の満席・自用だけの状態は共同開発前でも週−25,518円だった。需要が満席まで届くことと会社が黒字であることは別であり、着工を常に勧めるものではない。借入があれば既存ルールで破綻するため、需要投資の前に価格・人員・費用と予測を見直す。

空き能力のある配置では商業が大きく効き、外部賃貸の多い満席配置では賃貸だけが増益する。地区保有や能力を無視して、二択を同じ平均収益へ均す設計にはしていない。上の条件が変われば、同じ週の予測から比較し直す。

統合検証は、旧v1保存の内容維持、不正な地区重複・未来着工週・工期・choice・余分な完了フラグの拒否、完成週の保存成功後に委任を停止すること、保存失敗時に未保存の完成を通知しないこと、再読込後の再開、10決算で維持費が二重計上されないことを確認する。完成週の停止時点では直前週の決算が保存済みであり、完成効果はこれから終了する今週の予測に出る。
