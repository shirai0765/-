# 資金調達の比較

財務画面の `CapitalPlanningPanel` は「今は調達しない」「指定額・指定期間の借入」「IPO、上場後は10%増資」を同じ週で比較します。融資は10万円以上・追加借入枠以内、返済期間13〜260週。操作は既存の `GameAction` を明示的な実行ボタンから渡します。候補選択、入力、表示だけでは会社も週も保存データも変更しません。

`getCapitalPlans` は `applyAction` の結果に `getSummary` と `previewWeek` を適用します。独自の利益計算や将来の固定成長率は置きません。現金、借入残高、創業者持分、営業利益、利息、利息控除後利益、元本返済、支払配当、現金増減、週末現金を現状と比較します。IPOは既存株数の25%を発行、上場後の10%増資は調達額の5%控除と創業者持分20%下限をエンジン通り反映します。IPO未達条件、融資枠超過、不正入力、ゲーム終了時は実行不可理由を表示します。

任意の「計画支出」「支出後に残す現金」は、プレイヤーが選んだ投資の価格と留保方針を入力する計算用メモです。例えば駅周辺共同開発600万円・留保200万円なら必要現金800万円と調達案の即時現金を比べます。不足額を借入希望額へ入れる操作も、融資自体は実行しません。自動で案件を取得せず、この金額から投資後の営業利益や維持費を推測しません。調達後は投資先の実際の予測を確認するよう表示します。

借入残高がある週に「営業利益−利息」が0以下なら、現金・受取配当・その週の元本完済で回避できない倒産警告を表示します。黒字でも元本等で週末現金が不足する場合は別の警告です。調達は時間を進めないため、警告がある案も明示実行は可能です。借入直後に店舗運営を改善したり投資したりする既存の自由を奪わず、週終了前に再判断できます。

配当0%が会社の成長資金を残す目的に有利な現行仕様を明記します。創業者個人資産や新たな統治効果、借入救済、資金が貯まる週数の保証は追加しません。非上場を別エンディングとは扱いません。

## 0.4.1 の表示順

調達方法を選ぶと、得る現金・週末の現金、自分の持分・今週の元本返済、今週の利益（利息後）を表示します。借入希望額と返済期間の入力は借入を選んだときに表示し、IPO 等へ切り替えて戻っても入力を保持します。借入中の利益 0 以下と週末現金不足の警告、その案の実行ボタンは詳細の外に置きます。警告は利益と現金を別々に扱い、配当 0% が会社成長に有利な現行仕様の説明も残します。

現在と選んだ案の正確な 10 行対比は「現状と比べる・10項目の内訳」で展開します。計画支出・留保額の編集も別の展開欄にし、既に入力した額と不足は実行前に要約します。詳細の開閉・方式選択・入力・戻るは経済や週を変えません。全桁の金額、現金と利益の区別、危険警告を省いた短縮ではありません。

## 投資先との接続と入力メモ

基本の組込みは `<CapitalPlanningPanel state={state} onAction={act} disabled={busy || state.gameOver} />`。返済契約一覧・配当設定は既存機能を使用します。投資の文脈と画面間の入力保持には次の optional props を使います。

```tsx
<CapitalPlanningPanel
  state={state}
  onAction={act}
  planningContext={{
    id: 'rail:sakuragaoka:commerce',
    label: '桜丘・駅前回遊の共同開発',
    spending: 6_000_000,
    returnLabel: '共同開発に戻って確認',
  }}
  onReturnToInvestment={returnToInvestment}
  initialDraft={financeDraft}
  onDraftChange={setFinanceDraft}
/>
```

`planningContext` は `{ id: string; label: string; spending: number; returnLabel: string }`。ID は投資対象・方式を識別するものです。同じ投資の再計算価格を毎回強制代入するためのものではありません。

- 最初の mount では同じ `contextId` の `initialDraft` があれば編集済み支出を復元し、なければ渡された支出を入れて計画メモを有効にします。
- mount 中に異なる `context.id` が来た場合は支出を新しい対象の額に差し替え、計画メモを有効にします。留保額・借入額・返済期間・選んだ調達案は保持します。
- 同じ ID の通常更新・週進行・対象価格変更では、編集済み支出や留保額を上書きしません。計画を無効にした選択も保ちます。対象を外したときは対象名と戻る導線を外し、入力金額は残します。
- 対象の取得済み状態や実行条件をこのメモで判定しません。概算メモであると明示し、戻り先が現在の価格・条件・投資後の予測を確認します。戻る callback は調達や投資を実行しません。

`CapitalPlanningDraft` は UI 専用の入力を公開します。

```ts
interface CapitalPlanningDraft {
  borrowAmount: number;
  borrowWeeks: number;
  selectedId: 'hold' | 'borrow' | 'equity';
  useBudget: boolean;
  spending: number;
  reserve: number;
  contextId?: string;
}
```

`initialDraft` は mount 時の初期値であり、親から毎回入力を制御する prop ではありません。`onDraftChange` は mount 後と入力変更後に通知します。親は React の state setter など安定した callback を渡し、同じ会社で財務画面を開き直すときに最後の draft を返します。詳細欄の開閉は保存しません。空の数値入力中は `NaN` を保持でき、エラーとして表示します。GameState・保存形式へ入れず、ページ再読込後の復元は保証しません。会社の新規作成や保存インポート時に親が draft を破棄する契約です。

検証: `npx vitest run tests/capital-planning.test.ts`。実操作との一致、非破壊性、IPO/増資、持分下限、不正融資、返済期間差、利益ゼロでの倒産、元本による現金不足、予算入力の分離、終了済み状態を検証します。人間の楽しさや長期キャンペーンの成立は、この単体検証だけでは証明しません。

0.4.1 の UI 検証では、詳細を閉じたまま主要 5 値と両警告・実行/戻るが読めること、同 ID の値保持、新 ID の支出だけの切替、画面を離れて戻ったときの draft 復元を別途確認します。過去の 0.4.0 ブラウザー結果を今回の展開操作や文脈保持の検証結果とは扱いません。
