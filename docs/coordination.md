[公開サイト](https://shirai0765.github.io/-/)の版とsource commitは `release.json` と親の公開記録で確認します。0.8.0の街拡張は公開済み。0.9.0では選択済みB案のUI・演出を実装し、外部班から元の仕様に必要な素材と知見を受け取っています。ブラウザー内のセーブは個人の端末にあり、この文書からは見えません。

## このクラウドの担当

6つのサブ担当はGPT-6.1 Sol・極高。親が統合・リリースを持ち、街側の副統括が座標とファイルの境界を調整します。同時実行は親を含め7体。GPUブラウザーは1本、全体テスト・本番ビルド・公開は親だけが実行します。

| 担当 | 作業 | 専有する範囲 |
|---|---|---|
| 親 | 設計、統合、比較、リリース | 版番号、配布・公開・担当記録、最終Git操作 |
| 街・出店 | B案の物件画面、外部GLBレビューと配置案 | Appの物件ラッパー、PropertyScene、StoreOpening、SiteContextと専用CSS |
| 経済UI | 銀行・株式市場・グループ・営業提案・開発・資金計画 | 対応6パネルと専用CSS。金額計算と経済式は維持 |
| 共通基盤 | フォント・素材アイコン・共通テーマ、外部ニュース独立レビュー | GameIcon、theme、shared dialog、素材manifestと指定資料 |
| 操作・週次 | 全画面の営業結果・ニュース・達成と短い確定演出 | 対応8UI/CSS、意味のある演出テスト |
| 音 | 既存AudioContextへの素材・短い操作音の統合 | src/audio、CityAudioControl。外部素材の実到着を待って有効化 |
| 品質 | native画面・保存・入力・音・prefix・CSP | scripts/smoke-v090-native.pyと検証記録。GPUはこの担当1本のみ |

0.8.0は72物件／349景観候補、598テスト、本番CSP4カテゴリ、公開WebKitの開業→実決算→完全一致保存を確認して公開済みです。旧LOTS全158件の並びと旧48物件の値、109・実測写真モデルを保持します。[確定記録](interaction-v080.md)を参照してください。

## 追加のCloud Codexタブ

ユーザーの最新指定は、親側を管理・設計・統合・QAへ寄せ、元の仕様に必要な仕事を外部の既存1タブへ広く渡すことです。外部班は**継続して成果物を提出する班**へ拡張します。最初の20〜30ニュースは提出batchで、任務全体の上限でも停止点でもありません。独立した他社シミュレーションや汎用アセット基盤は増設しません。第二タブは予備のままです。

追加主担当の指定はGPT-6.1 Sol / max、子6担当は同モデル / high、主担当を含め最大7体、孫agentなしです。[PR #2](https://github.com/shirai0765/-/pull/2)の受領書（head `407236858c287a3060c224967489010e669d1eea`、基点 `12c375a`、1ファイル47行）を親が読取確認し、`game-source` へ取り込み・push済みです。受領書は主担当＋6担当の稼働と子担当のSol/highを報告していますが、主担当の正確なモデルは取得できないと記載しています。これは担当側の報告であり、この親が外部のモデル・稼働を独立に計測した結果ではありません。[追加6streamの指示](https://github.com/shirai0765/-/pull/2#issuecomment-6031934250)も親が投稿済みです。

- [環境とリポジトリの開始手順](external/teams/bootstrap.md)
- [外部制作・調査班への継続指示](external/teams/news-research-team.md)：ニュース、BGM、効果音、プレイ検証を小PRで順に返す。
- [予備の検証班](external/teams/qa-reserve-team.md)：親が具体的なPRと範囲を割り当てるまで待機。

実際の過去ニュースは事実の参照資料です。記事の本文に会社の別名を入れただけで再配布しません。ゲームのニュースとして採用するときは、歴史資料と、その会社で実際に保存された出来事を区別し、起きていない買収・出店・業績を実績として掲載しません。株価や保存済み経営結果を文章に合わせて改変する仕事は調査班へ割り当てません。

初期の4出典担当＋編集＋QAによる約24件は、小PRまで完了させて保持します。完成して空いた既存担当から役割を移し、次の6streamへ進みます。追加で6体を重複起動せず、担当交替時は元の原稿とファイル所有を引き継ぎます。

有限の初回成果物は**ニュース80件＋BGM2曲＋SFX kit＋3 play traces**です。初期pilotの採用品は80件に含め、件数を重複計上しません。小PRを出したら、レビュー待ちの間も独立した未完了作業を進めます。既存runtimeへの組込み・最終catalogの採用・source修正・merge・公開は親側が担当します。`src`、App、音声runtime、engine、storage、Vite、package/lockは、親が個別に専有ファイルを委譲するまで変更しません。ユーザーはUI案B（モンスト系）を選択し、各page・font・利用条件を満たすicon・報酬animationの実装を許可しました。この改修は親側が別の専有範囲を割り当てて実施し、外部班の6streamへ無断で追加しません。

外部主担当はtask境界とPR提出時に最新の `game-source` のこの文書と、親からのPRコメントを確認します。確認後は割当済みqueueを進め、レビュー待ちだけを理由に全員を停止させません。初回成果物が全て揃ったら、親へ完了と次の割当を照会し、未依頼の新機能を作りません。

この親タスクから別タブを自動作成・起動する機能は確認できていません。ユーザーが新しいタブで開始指示を渡し、受領PRが届いた時点から、この担当表とPRで作業・レビュー・取り込みを管理します。

## ドットなど、別タスクから参加する担当へ

ここでいうドットは、ユーザーが利用しているChatGPTのパーソナルエージェントです。このホストには、ドットを起動・停止する接続がありません。GitHub経由の受領・PRの経路は確認済みで、D01制作指示は[受領PRへのコメント](https://github.com/shirai0765/-/pull/1#issuecomment-6031539956)で送信しました。親が確認できるのは共有されたブランチ・PR・報告であり、外部の実行状況を直接監視しているわけではありません。

以下は成立した受領手順の記録です。最初に `game-source` を基点に `dot/receipt-v080` ブランチを作り、`docs/external/dot/receipt.md` 一つだけを追加します。コード・モデル・他の担当ファイルは変更しません。記載内容は以下です。

- この担当表を読んだ基点コミットと日時。
- リポジトリを読めるか、ブランチへ書けるか、PRを作れるかの実際の確認結果。
- 引き受ける作業番号（D01：模型用の資料・独立アセット、D02：公開画面レビュー）。
- 自分のタスクURLを共有できる場合はそのURL。秘密情報・トークン・個人のセーブは書かない。

ブランチをpushするかPRを作成し、その場所をユーザー経由でもよいので親へ返してください。親が受領内容を確認して、この文書のD00を「確認済み」に更新したら受け渡しが成立します。GitHubへ書けない場合は、確認できた範囲を本文で返してください。書込成功や自動連携を仮定しません。

以後は「親が作業番号・専有ファイル・完成条件を書く → 外部担当が受領と基点を記録 → 専用ブランチ／PRで返す → 親がレビュー・検証して取り込む」の順に進めます。外部担当がこの文書を再確認するタイミングや、次の実行を開始できる条件は受領時に共有してください。親が外部担当を自動起動できる前提にはしません。

まずこの文書と [最新の仕様と検証](interaction-v070.md) を読み、`game-source` の最新版を基点に独立したブランチを作成してください。親の編集中ファイルと同じ場所を変更せず、完了時はコミットまたはPRと短い検証報告で受け渡してください。公開ブランチへ直接反映しないでください。

外部担当に分離できる仕事は次の2件です。

1. **街の模型用の追加資料・独立アセット**：渋谷の雑居ビル、路面の飲食ビル、集合住宅を各1種以上。参照した実写真のURL・出典・取得条件を記録し、既存の109やPLATEAUデータを置き換えない。モデルを作る場合は単位m、+Yが上、接地面Y=0、原点を建物中央、外壁の正面方向を明記する。GLB、サムネイル、寸法、頂点／三角形／材質／テクスチャ容量を添え、まず軽量な1棟をレビュー可能にする。保存先は `public/models/external-v080/`、生成スクリプトは `scripts/external-v080/`、資料は `docs/external/dot/` に限定する。街への配置と既存レンダラーの変更は親側が統合する。
2. **公開画面の初見操作レビュー**：新会社→物件選択→開業→一週終了→ニュース→銀行の金額・期間選択→審査、の迷った箇所を記録する。利用端末・ブラウザー・版・再現手順を添える。既存プレイヤーの保存を削除せず、検証用ブラウザープロファイルを使う。コード修正は行わず、`docs/external/dot/` に報告する。実機Safariで音を聞けた場合は、実音声を聞いた範囲と操作だけを明記する。

他の担当の作業を上書きするforce pushや、本番の設定変更は不要です。外部タスクのURL・ブランチ・成果物が共有されたら、親がこの担当表へ追加して重複を避けます。
