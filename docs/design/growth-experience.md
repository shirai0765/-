# 最初の0〜3時間：判断が成長として返る体験

状態: 0.3.1のコード・既存検証資料を読んだ設計。以下の時間、面白さ、達成率は未検証の目標。0.3.1のQA基点確定後、新規出店の小実装を0.3.2向けに開始。成長担当は本書と結果表示を担当する。

## 最初に作る体験

「自分の店を開いた」→「選んだ運営で利益を出した」→「その利益をどこへ使うか選ぶ」の因果を短く見せる。報酬は会社の変化、判断の理解、街に残る自分の店。別通貨・無料資金・日次ログイン・取り逃し通知を増やさない。

創業からIPOまで同じ手順を強制しない。初週の複数出店、委任しない会社、早いIPOを認める。30時間は全108買収対象と街の完遂までの目標で、序盤を待機で引き延ばす理由にしない。

## 0〜3時間の体験目標

時刻は観察する目安で、ロック条件ではない。序盤の同じ状態を何十分も保つ必要はない。

| 目安 | 判断 | その場で返すもの | 決算後に分かるもの | 次の選択 |
|---|---|---|---|---|
| 0〜10分 | 地区・形態・予算を選んで開業 | 支払後現金、現週全社利益、自分の看板 | 初営業の売上・客数・純利益 | 価格/人員を直す、現状維持、次店を比較 |
| 10〜30分 | 価格・品質・人員のいずれかを比較 | 同じ週・同じ会社における変更前後差 | 採用した設定での保存済み実績 | 余力が需要不足か能力不足かを見る |
| 30〜60分 | 店舗改善・2号店・現金保持を比較 | 投資額、投資後現金、全社利益差 | 2店舗それぞれの寄与、既存店への影響 | 近隣集中か地区分散か、借入を使うか |
| 60〜120分 | 任せる店と自分で見る店を選ぶ | 委任料込みの利益差と変更案 | 実際の価格/品質/人員/広告、全社実績 | さらに拡張、運営を維持、委任を戻す |
| 120〜180分 | IPO・不動産・最初の地区投資の比較 | 資金の使い道と残る制約 | 資金・持分・街の変化 | 100事業と4地区を見渡す中盤へ |

初心者の初黒字を60分後まで待たせる設計にはしない。3時間時点で上場前でも、利益・再投資・委任の意味を説明できれば学習は進んでいる。上場が早くても、それだけを不合格にしない。

## 実は弱い分岐と優先度

**優先1: 設備・広告の効き方。** 来店数は需要と処理能力の小さい方。需要不足の店に設備を足すと売上が増えず週運営費が増える。能力が詰まった店に広告を足すと費用だけ増える可能性がある。現在の「設備増強」「品質」表示を成長ボタンと誤認させない。改善前後の全社予測を示し、無効な投資にはそのまま「今週の予想利益は減ります」と表示する。将来の需要増を期待して買う選択は残す。

**優先1: 委任を報酬にするが、利益増を保証しない。** 初店から委任できるため解除イベントで盛り上げる案は成立しない。創業者の役割が運営調整から立地/資本配分へ移ることが報酬。委任前に、自動変更予定と報酬込み差額を読む。週報では担当者が何を変えたかを短く返す。利益が減ったら手動に戻せる。ただし決算で採用済みの設定は、チェックを外すだけで委任前へ戻る現仕様ではないので、解除を「完全な元通り」と表現しない。

**優先2: 形態・立地を名目上の三択にしない。** 現時点で全地域の非劣位性は未検証。前提付きの「小さい初期投資」「現週利益」「満足度」を示す。候補が同じなら1案としてよい。プレミアムが見た目だけで恒常的に劣位なら、装飾で隠すのでなく地域需要/費用の後続バランス調整対象にする。

**優先2: 調達の機会費用。** 現金保持と借入には終了条件・返済の違いがある。一方、増資の持分低下は20%下限以外の経営上の不利益が弱く、配当支出は完遂への資金を減らす。比較表だけで複数の同等な戦略になったとは言わない。後続で持分維持の経営裁量・長期方針の価値を検討するが、空のスコア倍率で正当化しない。

**優先3: 後半の100取得。** 取得数だけの10件ごと報酬は同一操作を強める。「取得時の判断→引継費用→稼働した利益→次の資本配分」の違いを記録する。市場企業の業種が地区に直接効果を与える仕組みは現状ないため、地区との連動は将来仕様として扱う。

## 挫折に対するプレイヤーの手段

- 借入前: 現金が残る無借金赤字は調整して回復できる。初失敗に報酬を没収する追加ルールは不要。利益を出さないまま借りると危険であることを予測で伝える。
- 借入中: 全社純利益 `営業利益−利息 <= 0` は従来どおり終了。猶予週・確率救済・配当で帳尻合わせは入れない。設定変更、契約整理、全額返済、資産売却を実際の予測付きで比較する。資産売却そのものは営業赤字を直さず、返済資金を作る等の間接手段である。
- 2号店失敗: 新店だけでなく既存店の利益低下を示す。価格変更、地区分散、閉店の違いを考えられる。閉店回収は元の開業費の15%であり無料リセットと案内しない。
- 行動しない: 運営維持は正当な選択。利益が安定して次の投資を待つ週に架空の会話や罰を差し込まない。連続営業は新しい判断点や破綻予測で止まる。

## 3人の議論で変更した案

決定分岐担当から「2〜3候補を等しくすすめると、死んだ分岐へ初心者を誘導する」と反論を受けた。成長担当の当初案は修正し、**条件付きの比較・候補重複を許す**方針にした。主体性は候補数でなく、理由を理解し別の条件なら選び直せることで測る。

テンポ担当とは「最初の12週を一週ずつ読むと学べるが、学べた後も同じ確認を強制すると委任という成長を損なう」を議論した。今回は現行12黒字週条件を維持して測る。待機が多ければ早期連続営業の別比較を行う。IPOの実時間を遅くする解錠条件にはしない。

3人が推す次の共通スライスは **新規出店の比較→開店後の初決算→次の使い道** に絞った。初店と2号店を同じ仕組みで扱い、別の実績バッジ群を先に追加しない。調達だけの比較は資金の使い道が抜けるため、出店の手段に位置付ける。

## 最初の実装スライス

### プレイヤーから見た完了形

1. 空き区画で出店を比較すると「開業費を払った後の現金」「出店前→出店後の現週全社純利益」を短く確認できる。2号店以降は既存店への競合と本部費を含む。
2. 同じ面から自己資金で出店でき、地図の実際の看板へ戻れる。資金不足時は既存の財務画面へ案内する。融資と出店の一括実行は今回見送り、借入を必須にしない。購入額を満たしても週末現金が不足する場合は別途警告する。
3. 週を進めて保存に成功すると、同じ出店記録へ「開店後の初決算：第N週全社純利益・現金増減・新店の来店者数と店舗利益」を接続する。出店後に設定/契約等を変えた場合は「その後の変更を含む最終計画」として区別する。出店後利益のすべてを出店だけの効果と表現しない。
4. 結果の下に「この店を改善」「次の出店候補を比較」「この運営を続ける」を置く。黒字なら必ず拡張させる推奨にしない。会社全体の赤字や資金不足がある場合は警告を先に出す。

表示例（数字は必ず実計算値）:

> 2号店を開業しました。第8週の全社利益予測：出店前X円 → 出店後Y円。支払い後の現金A円。
>
> 開店後の初決算を保存しました。第8週全社利益B円、現金増減Z円、新店の店舗利益C円。出店後の他の操作も含みます。
>
> この店の運営を見る / 次の出店候補を見る / 現状を維持する

### 実装境界

- 経済式・価格・借入終了条件・12黒字週条件・30時間完遂条件を変えない。0.3.1検証済み配布物を上書きしない。
- 最小対象は新規出店の1種類。委任・設備・IPOの独自記録、全行動の詳細履歴、自由記述の必須回答、音声、カメラ自動移動は不要。所有店への既存リンクを再利用する。初店/2号店は出店時の店舗数から表示し、別の実績保存は増やさない。
- 比較の計算は同じstateに対する既存 `applyAction` と `previewWeek` を使う。別の簡易利益式をUIへ複製しない。無効な操作は費用を払う前に理由を表示する。
- 変更前後の比較と、前週実績からの差は別もの。後者は賃金・需要・信用等も変化するので「この操作で利益が増えた」と断定しない。
- 同週の複数出店や設定変更は最後の1項目だけの効果にまとめない。出店時の予測と決算時の全社実績を区別する。初営業前に閉店した場合は、別店舗の利益を結び付けず「初営業前に閉店」とする。
- 保存失敗時は「保存済み」「成長を記録しました」と表示しない。連続営業では対象週のcommit成功時に確定し、途中停止/再読み込みで同じ結果を重複発行しない。
- 既存セーブへ省略可能な出店記録を追加し、識別子・週・数値・対象店を検証する。旧セーブの不明な出店時予測を推測で埋めない。今回の記録は最近40件に限定し、生涯の初達成アーカイブとは表示しない。
- 「初めて達成した」は過去の事実。「現在2店舗を運営」「現在委任中」は現状態。閉店/委任解除で過去を消さず、過去の達成が現状の黒字や完遂を保証する表示もしない。

対応箇所は `src/App.tsx` の操作/週報、独立した比較・記録コンポーネント、`applyAction` / `advanceWeek` 共通フック、必要最小限の保存検証。`src/model.ts`・`src/persistence.ts` 側の互換を扱う。都市側に追加メッシュを求めず、モデル担当の作業と衝突させない。責任分担はrootがApp/engine接続、決定分岐担当が比較helper/UI、テンポ担当が保存型/検証、成長担当が `src/ui/OpeningResults.tsx` と専用CSS。QA基点確定後の実装GOを受けた。

## プレイテストの合格基準

初心者4名・経営ゲーム経験者2名を目安に、最初の30分を観察し、可能な参加者で180分まで継続する。これは小規模な設計判断用で、30時間全体の統計的証明ではない。離席は除外し、比較・調整・地図観察・同じ週送りだけの時間を分ける。

| 見たいもの | 暫定基準 | 不合格時に直すもの |
|---|---|---|
| 最初の成功が早く分かる | 6人中5人が15分以内に初決算へ到達。初黒字の有無は別記録 | 候補比較・開業/週送りの発見性。現金ボーナスで補わない |
| 自分の判断を理解する | 6人中5人が直前に変えた設定と、同週予測がどう変わったか説明できる | 比較表示と用語 |
| 利益と資金繰りを分ける | 借入・元本返済を扱う課題で6人中5人が純利益と現金増減を区別 | 決算の因果表示 |
| 厳格な借入条件を理解 | 危険な状態の課題で全員が週送り前に終了条件を説明できる | 予測・警告・修正導線。ルールは緩和しない |
| 形だけの成長を買わない | 需要不足の設備増強と能力不足の広告について、6人中4人が利益を比較して判断 | ボトルネック表示。全員に同じ答えを要求しない |
| 委任の結果を読める | 委任した全参加者が、報酬と採用された設定の少なくとも1項目を把握 | 委任前後と週報の接続 |
| 2号店は自分の意図 | 開いた参加者が、既存店改善/現金保持より選んだ理由を一つ説明 | 比較候補と全社差額。出店率100%を目標にしない |
| 操作の空白を減らす | 最初の3時間のうち、判断も新情報もない週送りだけが20%未満 | 重複報告・連続営業の条件。人工イベントで埋めない |
| 報酬を邪魔にしない | 節目表示が追加の必須確認を増やさず、再読込で二重に祝わない | 通知と記録の分離 |

機能検証は、同週比較の現金/利益整合、借入ありの純利益0境界、単週と連続営業の同じ記録、保存失敗での未確定維持、再読込重複なし、旧セーブ互換に絞る。経済を変えない本スライスだけで長期バランス全探索を回す必要はない。30時間の証明は別途、人の全編プレイで行う。
