# 0.8.0：街の密度と選べる物件を増やす

## 目的と現在地

既存の48取引物件を保持し、4地区の外周へ各6件を加えて72物件にした。景観表示候補は270棟から349棟へ増やし、道路、貸出の目印、自社の店を読める街にする。初期の俯瞰を遠ざけることなく、外周へ移動し、比較して出店できる範囲を広げる。

2026-10-07時点の担当間契約と受入結果。各担当の実装とfocused CPU検査、親担当の全598テスト（67ファイル）と本番build01、本番CSPのnative4項目が完了した。DEVのnative機能6項目は完了したが、終了処理の検査脚本不具合によりDEV総合結果はfalseとして保持する。配布物の生成・整合確認も完了し、公開サイトでの検証は親担当へ引き継ぐ。静的検査、機能確認、総合合否を区別する。

## 保存と既存経営の契約

- 元48物件のID、順序、座標、寸法、人通り、客層、賃料、購入価格、説明を保持する。新24件は旧 `LOTS` 全件の末尾へ追加し、旧配列の参照位置も保持する。
- 元の道路は移動しない。新道路は別IDで末尾へ加え、既存の外周道路へ接続する。
- 新物件も `Lot` と既存4種の `DistrictId` を使い、`available: true` とする。初期資金、利益計算、seed/RNG、保存versionを変更しない。新物件の購入・出店には既存の操作を使う。
- キャンペーンは既存8社・市場100事業・稼働する4地区のまま。72物件の全所有を完遂条件へ加えない。既に保存した達成記録も保持する。
- 109系ランドマーク、Blenderモデル、写真、実測モデル、実測表示に対応する4地点はこの変更の対象外。新しい架空街区へ実測対応の表示を付けない。

| 地区 | x | z | 件数 |
| --- | --- | --- | ---: |
| センター街北 | −78、−20 | −360、−400、−440 | 6 |
| 桜丘南 | −78、−20 | 360、400、440 | 6 |
| 道玄坂西 | −360、−400、−440 | −29、41 | 6 |
| 宮下・東口東 | 360、400、440 | −72、44 | 6 |

区画中心は原点から半径450m以内とし、店舗の近接視点も既存のpan上限460mを考慮する。初期camera位置 `(-290,255,325)`、FOV36、地面1100m、fog590〜1250mをまず維持する。影の範囲も、必要性を測らずに広げない。

道路は2点の軸平行segmentとして追加する。旧コードには最初の2点だけで道路の予約領域を作る箇所があるため、新しい折線1本を渡して描画と予約判定を食い違わせない。

## 景観外観のAPI

新 `SceneryBuildings.ts` は次の関数を提供し、街担当が `CityView` の外周描画から呼ぶ。

```ts
addSceneryBuilding(
  art: CityArt,
  building: { x: number; z: number; w: number; d: number; h: number; seed: number }
): void
```

入力は既存 `OUTER_SCENERY` と同じ。外形は店舗近接視点の障害包絡内に保つ。

- x方向：中心x、幅 `w + 2`。
- z方向：中心 `z + 4.5`、奥行 `d + 11`。
- 上端：`h + (seed % 3 === 0 ? 6 + seed % 12 : 0) + 3`。

雑居ビル、オフィス、集合住宅の窓、外壁、屋上、地上階へ差を付ける。共有box geometryと既存paletteを使い、窓はopaqueとし、外部モデルや棟ごとの新textureを追加しない。材質・texture増加を原則0とする案は性能上の期待であり、実測結果は別に記録する。1棟の装飾は上限を設け、遠い建物の部材を細分化し続けない。

物件24件の追加だけで既存の空隙を埋めたとは判断しない。既存の202〜350mの外周も確認し、密度の改善と道路・目印の視認を同じ俯瞰で評価する。

## 一覧と操作の契約

`SiteBrowser` は `LOTS.filter(lot => lot.available)` から全件と地区・状態を表示する。72をUIへ固定値として書かない。

- 「地区ごと」は実際に4地区順へまとめる。元データ順だけに依存しない。
- 物件名と自社店名の検索を1入力にまとめる。0件から条件を解除でき、「全区画を表示」で検索も解除する。
- 購入価格の低い順を追加し、この並べ替え時に基準購入価格を表示する。保有済みの状態と売却額を混同しない。
- 候補、自社店舗、保有物件の小さな状態アイコンを付ける。街の目印と状態を対応させる。
- Safariの入力16pxと390px幅を確認する。常設パネルを増やさず、一覧からの選択だけで経営状態を変更しない。

全候補がゲーム街で同じID・位置へ到達でき、既存の出店・購入・財務から候補へ戻る操作を保つ。目印の優先順は金融施設35、選択中32、自社31、候補30を維持する。

未開業の候補と物件のみを保有する場所には、詳細から「街でこの建物を見る」を1つ追加する。明示した時だけ `App` が `sitePanRequest: { lotId, nonce }` を送り、ゲーム街を水平方向へ移動する。角度、FOV、距離、cameraとtargetの高さを保ち、通常の一覧・目印の選択ではrequestを作らない。新会社、保存の読込・復元、地図切替、店舗表示、鉄道表示、「街全体に戻る」ではrequestを解除する。実測対応の既存4地点では既存の実測表示への導線を使い、それ以外はゲーム街へ表示する。`CityView` は古い店舗・鉄道の近接表示を解除してから移動し、古い表示の終了処理で意図した移動を上書きしない。

ユーザーが希望した別のCloud Codexタブと第二orchestratorを、このhostから直接起動する接続はない。Dotパーソナルエージェント向けの指示は親担当の `docs/coordination.md` に置き、公開操作レビューやGLB・写真資料を別namespaceで受け取る。親担当はDotのPR#1を受領してfast-forwardで取り込み、連携文書D00の確認と7枠Astraのモデル指示を `game-source` へpushした。[PRコメント](https://github.com/shirai0765/-/pull/1#issuecomment-6031539956)での開始指示は投稿成功（HTTP201）を確認済み。これはこのhostから外部agentを直接起動した証拠ではなく、7agentの実際の起動と外部assetの提出・品質レビューはまだ未確認である。
