# キャンペーンの進行と成長の手応え

0.4時点の進行設計と検証範囲。v0.3.1〜0.3.2の記録を過去の基点として保持し、0.4で実装した沿線共同開発と完遂判定の統一を区別して記す。以下の時間・報酬頻度は人間のプレイで検証する仮説であり、この文書自体が30時間の体験を実測した報告ではない。

## 過去の基点から分かること

最終目標は上場、既存8社と市場100事業の取得・引継ぎ、4地区各3工程の完成・稼働。市場100件にはREIT運用資産5件を含む。全100件という有限の目標を維持し、途中の報酬のために達成条件を増やし続けない。

0.4前の `docs/campaign-market-results.jsonl` に記録した公開操作による2シードは次の経路だった。922／1,006週は比較の基点として保持し、0.4の結果へ上書きしない。

| 段階 | seed 1 | seed 2 | 読み取れる課題 |
|---|---:|---:|---|
| 3店舗 | 3週 | 3週 | 初期拡大は長い貯金待ちではない |
| IPO | 21週 | 21週 | 2〜3時間の実測ではない |
| 最初の市場取得 | 65週 | 69週 | IPO後に投資の選択が増える |
| 4地区完成 | 160週 | 116週 | 都市開発の達成が早く尽きる経路がある |
| 最初の鉄道 | 889週 | 849週 | 地区完成から729／733週後。街の変化を途中でも感じたい |
| 市場100件稼働 | 975週 | 887週 | 全件取得と引継ぎ完了は別の達成 |
| 全目標完遂 | 1,006週 | 922週 | 最後の大型鉄道が終盤の山場 |

324／332回の操作のうち200回は市場調査・取得。意思決定数や面白さの実測ではない。最長投資間隔36週は以前より短いが、「投資が発生した」と「新しいことを考えた」は異なる。13週進行もあるためゲーム週を実時間に変換しない。

地区完成が早いこと自体は失敗ではない。街づくりを優先した成果として認める。その後も会社・沿線・統合へ関心をつなげられるかを問う。鉄道会社の取得は子会社利益と列車の外観・会社表示に結びつく。0.4で追加した沿線需要・賃料の効果は、鉄道取得とは別の共同開発によるもので、鉄道を買うだけで同じ効果が付くわけではない。市場取得と地区用途の経済的な相乗効果はまだない。

## 0.4で追加した選択と通常経路

上場・信用45・地区内の直接保有物件を条件に、各地区1件の任意の駅周辺共同開発を選べる。商業600万円／4週／維持費週6,000円／自社店舗需要+12%、賃貸800万円／6週／週4,000円／外部賃料+16%の二択で、着工後の変更・中止・返金はできない。維持費は工事中から計上し、完成時の費用急増を作らない。地区開発との加算上限は需要+40%・賃料+50%。地区の最後の保有物件を売ると効果と費用を休止し、再取得で再開する。

満席の店では追加需要が利益へ変わらず、自用物件だけでは追加賃料が生まれない。商業・賃貸・見送りを資産構成に応じて選ぶ。確認画面は着工前後の同じ週の利益と現金を比較し、工事完了の未来利益を先取りしない。「沿線の様子を見る」で選んだ地区の都市表示へ戻れる。表示が報酬として伝わるかは人間の観察で確認する。

通常操作による2シード×3経路の結果は次のとおり。全経路でIPO21週、市場100件稼働・既存8社・4地区12工程を達成し、破綻なし・保存往復一致だった。

| seed | 共同開発なしの完遂週 | 商業の着工→稼働／完遂週 | 賃貸の着工→稼働／完遂週 |
| --- | ---: | --- | --- |
| 1 | 1,010 | 道玄坂21→25／1,002 | 宮下105→111／1,006 |
| 2 | 922 | 道玄坂21→25／958 | 宮下81→87／926 |

商業の早期着工は市場初取得をseed 1で65→81週、seed 2で69→77週へ遅らせた。最終完遂も毎回早まるわけではなく、常に着工が最適という結果ではない。共同開発は鉄道会社を所有する前の投資機会で、鉄道会社の安価な取得や新しい必達条件ではない。詳細と保存した生結果は [0.4の経路報告](../campaign-v4.md)、計算条件は [沿線共同開発](../rail-projects.md) を参照する。

これは2シードの経済的到達確認であり、30時間の実プレイ時間、意味のある判断の数、全物件・全出店地取得の検証ではない。全例は6店舗で完遂した。

## 30時間全体の山場

既存の約30時間という設計予算を、待機時間ではなく扱う経営課題の拡大へ配分する。順番は強制しない。早期の物件・市場取得・鉄道優先も許し、熟練者の速いIPOを妨げない。

| 時間の設計目安 | 主な問い | 小さな成果 | 次を遊ぶ理由 |
|---|---|---|---|
| 0〜1時間 | この立地でどう黒字にするか | 初利益、設定変更の結果、店の営業風景 | 違う立地でも通用するか |
| 1〜2.5時間 | 自分で運営するか任せるか | 2号店、初委任、3店舗、IPO条件 | 店の利益で会社の選択が広がる |
| 2.5〜7.5時間 | 家賃を止めるか賃貸収入を得るか | 初物件、最初の工事・完成、地域の見た目 | 他の地区では違う組合せが効くか |
| 7.5〜14時間 | 何を取得し、どう引き継ぐか | 初取得、準備終了、実際のグループ利益 | 次の事業に使う資本の選び直し |
| 14〜22時間 | 鉄道・沿線へ資本を振り向けるか | 鉄道保有、列車表示、地区との完成風景 | 残る大型事業と街の構成を完成させる |
| 22〜30時間 | 残りの取得・引継ぎをどう終えるか | 残対象が減る、全件稼働、経営の総括 | 自分が選んだ会社と街が完成した納得 |

沿線共同開発の二択は0.4で実装したが、鉄道会社固有の運営判断や統合後の追加経営課題は候補のままである。沿線投資の解放をこの時間表まで待たせない。現行100件を30時間へ引き伸ばすだけでは、この表を満たせない。

全100件は必達条件だが、途中の取得順・投資配分・統合方式で経路を変える。残り10件に新しい意味がなければ、強制の追加調査や取得価格引上げで終盤を長くしない。まず一覧比較・選択済み候補の再確認など操作負担を減らす。複数件をまとめて取得する仕組みは資金と準備費を合算して明示する別設計が必要で、無確認の自動取得は導入しない。

## 報酬の頻度と意味

報酬は無条件の現金配布でなく、自分の選択が読める結果と新しい使い道を中心にする。

| 頻度の仮説 | 報酬 | 表示の単位 |
|---|---|---|
| 操作直後 | 選択前後の同じ週の全社予測、支出後現金、街の変化 | 小さな差分。毎回の祝賀モーダルは不要 |
| 次の決算／工事・引継ぎ終了 | 保存できた実績、何が稼働したか、次に選べる案 | まとめた結果。予測と実績を区別 |
| 活動中10〜20分程度 | 新しい能力・初回の達成・比較する課題 | 初店、初委任、初物件、初市場稼働など |
| 活動中45〜90分程度 | 遊び方が変わる大きな達成 | IPO、地区完成、初鉄道、全件稼働など |

10〜20分・45〜90分は達成を時間でロックする仕様ではない。人間の観察で成果の空白を見つけるための目安である。慎重に比較を楽しんでいる時間を「退屈」と自動分類しない。逆に同じ取得クリックだけを高速に重ねても、小さな報酬が十分とは判定しない。

取得数10件ごとの架空ボーナス、毎週の称賛通知、利益が上がらない会話で内容を水増ししない。稼働数の節目は進捗の目印としては使えるが、経済的な判断や地区の変化と同数に数えない。

現行 `getProgression` は現在の保有・稼働条件で表示する目標、`milestones` は一部の過去実績である。店舗売却・地区休止後も「初めて完成した事実」は残し、「現在4地区稼働」は別に表示する。永久実績を最終完遂条件の代用品にはしない。

## リスクを理解できるから続けられる

借入があり、週次の利息後利益がゼロ以下なら倒産、というユーザー指定を維持する。借入猶予・自動借換え・配当による赤字救済は追加しない。資金不足による終了も別に説明する。

利益が上がる投資でも現金・利息・準備費・元本返済を圧迫しうる。次の黒字だけを強調せず、取得時の支払と、準備中・稼働後の費用を分ける。同週の確定予測は確定予測として出し、将来の収益幅や「このままなら何週後」という仮定と混ぜない。

委任中の危険予測停止は現行どおり週を進める前に行う。停止は救済ではなく判断を返す機能で、通常の1週終了を選べば同じ倒産ルールが適用される。成長の演出によって危険表示が隠れたり、同意した借入が黙って実行されたりしない。

小さな失敗から学べるのは、次週を終える前の設定比較や借入前の投資判断。厳しい倒産ルールを維持したまま、ここで検討をしやすくする。新しいランダム損失を隠して難しさを作らない。

## 委任と反復操作

12黒字週後の4／13週進行は現状を基準に観察する。成長担当との検討では、学習成功後も必ず12回手動操作させる方向への強化を採らなかった。ゲートを早める案も今は未決定で、まず待機が多いかを測る。

現在の `runManagedWeeks` は各週保存後、新営業提案・IPO条件・地区開発完了・沿線共同開発完了・市場引継ぎ完了で停止する。沿線は保存した状態が完成週へ入った直後に止まり、その時点の今週予測に新しい効果が出る。直前週の決算に完成後効果を遡って加算しない。後半は引継ぎ完了が大量に発生するため、停止回数の増加が取得のご褒美を通知処理へ変える危険がある。

- 初めての稼働、次の工程を選べる開発完成、危険予測はプレイヤーへ戻す価値が高い。
- 後半の同じ種類の稼働完了は、将来は「期間末にまとめて確認」を選べる候補。ただし危険停止や未処理の新しい経営判断をまとめて飛ばさない。
- 同種完了をまとめる設定は次の実装候補であり、0.4では実装していない。保存成功後に通知する順序と、危険な決算前に停止する仕様を維持する。
- 最大投資間隔に加え、停止理由別の回数、止まってから何も変更せず再開した割合を見る。

## 0.3.2で比較・実装した出店記録の経緯

以下は0.3.2で出店記録へ絞った当時の比較であり、0.4全体の実装範囲ではない。成長担当の「判断前後の予測と保存済み実績の接続」を先に進め、調達比較を後続の大型投資へ伸ばす方針とした。市場統合の新イベントは現在も後続候補である。

| 比較した案 | 利点 | 当時の扱い |
|---|---|---|
| 設定・初委任・2号店の判断記録 | 初期から選択の結果が読め、既存計算を使える | 最小sliceに推薦 |
| 内部留保／融資／増資の比較 | 大型投資への別経路を理解できる | 記録を接続した次のslice候補 |
| 統合後イベント・沿線固有計画 | 中後半に実質的な内容を増やす | 経済・都市表現を要する拡張 |
| 初期手動週や価格を増やす | ゲーム週・操作数が増える | 密度を改善しないため採らない |

相互検討の結果、実装候補はさらに**新規出店の1操作**へ絞る。初店から2号店への成長を既存の全社比較で説明できるためで、初委任・設備・IPOの記録は後続とする。自己資金出店を軸にし、融資比較は複合実行の安全性まで扱える次のsliceへ回せる。

最小sliceは出店について、(1)変更前と変更後の同週全社予測、(2)実行時の店・出店週・手元資金、(3)その店の初決算と実際の全社決算、を連続して見られる記録。決算前の追加変更があれば、出店時予測と最終営業設定の違いを明記する。選択が週の利益を変える因果効果と、前週からの実績差は分ける。人流や他資産も動くため、「実績差の全ては今回の投資のおかげ」とは書かない。

既存の接点は `applyAction`／`previewWeek`、`App.tsx` の操作・決算保存、`runManagedWeeks` の `onCommit`、成長戦略・経営記録画面。出店済み・取得済みの件数だけでは選択時の比較値を復元できない。最初は対象操作を絞り、経済値やセーブ形式の恒久拡張を増やしすぎない。保存をまたいで残す場合は、初回達成週の不明な旧セーブに架空の過去を補完しない。

実装へ進めた状態契約は任意項目 `openingRecords` の最近40件。520週で切り詰められる収支履歴と独立して出店時比較・初決算を保存するが、41件目以降は古い出店記録から外れる。永久実績の保管庫とは呼ばない。初営業前の閉店も終端状態として保持し、同週同区画の再出店と結びつけない。旧セーブの過去出店は未記録のまま。全社予測に加え、出店時の単店利益予測 `initialStoreProfit` を保存して初決算の単店実績と比較する。

受入条件は、同週比較であること、保存成功後だけ実績と呼ぶこと、4／13週進行・中断・再読込で同じ達成を重複表示しないこと、危険警告を優先すること、記録から次の経営画面へ戻れること。利益を変更しない表示のsliceであるため、30時間の内容完成とは報告しない。

0.4以後も残る優先順位は次のとおり。出店記録や沿線の最大4選択だけで、中後半の体験密度が十分になったとは判定しない。

1. **買収100件の反復を把握し、比較操作を短くする。** 全件取得は維持。取得前の一覧比較、引継ぎ終了のまとめ確認を先に検証し、同型クリックを減らす。報酬の演出を増やすだけでは解決しない。
2. **沿線の二択が資産構成によって意味を変えるか観察する。** 0.4の共同開発で商業需要と賃貸用途を競合させ、上限・維持費・休止条件を実装した。次は実プレイで見送りを含む判断を確認する。鉄道会社そのものを早期取得する固有の理由は別の未解決課題であり、全鉄道を安くして収益率順の正解にする案は避ける。
3. **買収後の異なる課題を少数の業種群から試す。** 初めから100本を制作せず、飲食・不動産・交通など3系統で独立運営／共通投資に実質的な違いが出るか試す。既存の稼働待ちを追加の強制面談で埋めない。全100件の完遂条件に後付けで100回の新義務を足さない。
4. **4地区の完成形を持続する成果として見せる。** 完成後の買収・列車表示と視覚的につなげる。新しい任意計画を追加したために既存地区を未完成へ戻すことはしない。地区内容を増やすなら別目標として提示する。0.4の直近決算要件による完遂表示の修正は、新しい必達目標の追加とは区別して下記に説明する。

## 人間による検証

まず初心者3人・経営ゲーム経験者3人程度による45〜60分の観察を行い、操作の意味が読めるかを検証する。6人は初期問題を見つけるための規模で、所要時間の母集団推定には使わない。その後、同一開始条件から複数人が中断・再開を含めて完遂する長期観察へ進む。中盤セーブからの短時間検証は後半UIの検査に使えるが、30時間の通しプレイ時間に足さない。

観察は軽いローカル記録または手動シートから始める。データを外部送信する必要はない。

| 記録する項目 | 判定したいこと |
|---|---|
| 活動時間、明示休憩、非表示時間、ゲーム週 | 放置を除いた実時間。読む時間を無操作だけで放置と誤判定しない |
| 選んだ案、比較した代替案、短い選択理由 | 操作回数と意味のある意思決定を分ける |
| 決定前後予測、決算、初回達成 | 自分の操作が結果にどう結びついたかを説明できるか |
| IPO、初市場稼働、地区完成、初鉄道、全件稼働、全完遂の活動時間 | 進行の山場がどこに偏るか |
| 委任回数、停止理由、何も変えず再開した回数 | 判断のない中断や週送り反復の多さ |
| 同型取得が続いた件数・時間、次の目的を探した時間 | 100件取得が比較でなく作業になる場所 |
| 10〜20分ごとの目的・満足・続けたい理由、離脱理由 | 利益の上昇だけでは測れない成長の手応え |
| 全試行の破綻・中断・未完遂 | 成功者だけの所要時間に偏らない |

短期検証の見直し目安は、初黒字後に次の使い道を説明できない、同じ理由の単純取得が10分続く、判断のない進行再開に活動時間の20%以上を使う、15分以上次の目的を見失う場合。数値は暫定の診断基準で、超過を自動失敗やプレイヤーの能力不足としない。比較が楽しく長考している場合は別に記録する。

長期検証では完遂した全員の時間、未完遂人数、初心者／経験者の差、休憩除外方法を示す。観測中央値が約30時間であることに加え、空白と単純反復が許容できるかを確認して初めて「約30時間」を体験の説明に使う。17時間で密度高く終える熟練者に待機を追加しない。30時間を超える人の迷い・UIの読みにくさも内容の厚みとして数えない。

## 完遂判定の修正と検証の限界

0.4では `src/sim/campaign.ts` の `getCampaignCompletion` を画面・通常戦略・沿線比較戦略で共有し、直近の保存済み決算と今週予測の両方が黒字で完遂と判定する。従来の戦略検証もこの条件だったが、旧UIは今週予測しか見ていなかった。この不一致をコードで修正した。

沿線を含む0.4の新機能で取得対象や必達計画を増やしてはいない。一方、旧UIで直近赤字・ゼロの決算を無視して完遂表示していたセーブは、要件の厳格化により未完表示へ戻る場合がある。これは表示判定の不具合修正であり、保存された取引・利益・取得資産の書換えではない。新目標を後付けしない方針と、旧UIの誤判定を永久に維持することを混同しない。

既存の自動検証は経済の到達可能性と保存往復一致、今回の読み取りは進行上の仮説、人間の観察は面白さと所要時間を担う。30時間の通し実プレイは未検証。v0.3.1の描画QAやZIP確認と、これらのゲーム体験の検証も別の結果として報告する。

0.3.2当時の出店記録・保存・委任の検証報告は計37件通過として記録されていた。0.4では沿線の単体15件と保存・委任・枝比較の統合12件が通過し、共通完遂判定を使った通常6経路も完遂・破綻なし・保存一致を確認した。これらは各時点の検証範囲であり、現行全テスト数や表示の分かりやすさ、30時間の満足度を示すものではない。
