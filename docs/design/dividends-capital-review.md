比較対象は `rail_economy_v4` の [配当の選択肢](dividends-options.md)。資本担当としては、現版は C の正確な説明を維持し、将来の小さな検証候補として A を優先する。B は経済全体への影響と反復操作の抜け道が広いため、先に採用しない。

## 現在の計算をどう読むか

`src/sim/engine.ts` の `previewWeek`、`getSummary`、`ipo` / `issueShares` / `setDividend`、`advanceWeek` と、`src/model.ts` / `src/sim/campaign.ts` を読んだ。

| 記号・項目 | 現在の計算・扱い |
| --- | --- |
| N：今週の利益 | 営業利益 − 利息。受取配当、支払配当、元本返済を加減しない |
| D：会社が支払う配当 | 上場後に `round(max(0, N) × 配当性向)`。設定操作自体では支払わず、週終了の現金増減に入る |
| 会社の現金増減 | N ＋ 受取配当 − 元本返済 − D ＋ 契約満了の現金回収 |
| q：創業者持分 | 創業者株数 ÷ 発行済株数。配当の個人入金・経営権喪失・株主満足は現行にない |
| 会社評価 | `max(100万円, 純資産 + max(0, N) × 104)` を丸めた値。個人資産はない |
| 増資 | 操作時の会社評価から価格を計算し、新株対価の 95% が会社へ入る。創業者持分 20% が下限 |

同じ事業・投資操作を比較する限り、D を減らせば会社に残る現金が増える。現在は配当で得る別の便益がなく、会社成長・全取得を目的とするなら 0% が有利である。現金が残れば純資産とその後の評価にも寄与する。ここでいう有利は、すべてのプレイヤーの鑑賞・役割演技の好みまで否定する意味ではない。

持分低下には追加増資余地を減らす効果があるが、個人所得や議決権へは未接続。同じ週の増資を繰り返せることと、無制限に繰り返せることは別であり、現行の 20% 下限を無視して「無限増資」とは呼ばない。

## A：個人現金と任意の個人目標

### まず元帳を分ける

総配当 D を会社から一度だけ引き、決算時点の q に応じて創業者へ F、外部株主へ E を分ける案が最も説明しやすい。例えば `F = round(D × q)`、`E = D − F` とし、丸めた F と E の合計が必ず D に一致するようにする。会社から D を引いたうえで F も追加控除する、会社は F だけ払う、外部株主分も創業者へ入れる、という計算はいずれも避ける。

例として、利益等を計上した配当前の会社現金が 1,100 万円、総配当が 50 万円、q が 80% なら、会社は 1,050 万円、創業者の個人現金は +40 万円、外部株主への支払は 10 万円となる。会社＋創業者だけを合計すると 10 万円減るが、外部株主へ渡した分であり、消失でも新しい利益でもない。

| 区別する表示 | してはいけない混同 |
| --- | --- |
| 会社の今週利益 N | 創業者への F を会社の新しい利益として加算しない |
| 会社の現金 | 個人現金を店舗取得・元本支払・破綻回避へ自動で流用しない |
| 個人の受取配当 F | 自社の資金調達額、他社株の受取配当と混ぜない |
| 個人が持つ株の参考価値 q×会社評価 | 会社価値の全額を個人所有として足さない。未実装の売却で換金できる残高とも呼ばない |

個人の総資産参考値を置くなら「個人現金＋q×配当後の会社評価」のように所有割合を反映する必要がある。「個人現金＋会社評価全額」は外部株主分も個人へ帰属させる誤りであり、「配当前の持分評価＋受取配当」は同じ分配価値の二重計上である。この二つを分けて検査する。評価が会社現金の変化へ素直に連動する範囲では、会社から出した D による保有株価値の減少 qD と、個人受取 qD は対応する。評価の下限や他の事業変化があるため、この対応をあらゆる状態での時価保証にはしない。

### A で解決できること、できないこと

高い持分を保つと、同じ会社配当のうち個人が受け取る割合が大きくなる。一方、増資で事業を早く育て、低い持分でも将来の大きな配当を得る可能性がある。この比較は持分の意味を増やす。どちらが有利かは成長の時期・投資機会・個人の目的に依存し、持分維持を常に正解とするべきではない。

ただし、会社の全取得だけが目的なら依然として 0% が有利であり、A はその支配性を解消した案とは言えない。また、個人目標が単なる累計金額で期限も他の楽しみもなければ、成長を優先して最後にまとめて配当を始める方針が有利になりやすい。これを隠すために配当の強制期限・罰・追加必須目標を付けるのは今回の方針と合わない。

任意の個人目標に何をしたいかという意味がなければ、口座が二つの数字へ増えるだけである。採用前に「配当を受け取りたい理由」「会社への再投資と何を比較するか」をプレイヤーが説明できるかを見る必要がある。個人口座から会社への貸付・増資・自社株買いまで同時に足すと資金循環が一気に複雑になるため、最小案には含めない。

### 決算と保存に必要な境界

配当設定を切り替えた時ではなく、既存と同じ一回の週次決算に対して会社出金と個人入金を確定する。`previewWeek` を呼ぶ、比較を開く、保存データを読むだけで入金してはいけない。週内に増資した場合は決算対象状態の持分で配分し、どの時点の株数を使うかを明示する。

将来実装するなら、会社出金・個人入金・その決算の保存を同じ状態遷移に含め、再読込・再表示・保存再試行で同じ配当が増えないことを確認する。過去に個人配分を記録していない旧セーブから、現在の持分を使って過去の個人資産を作り足さない。新しい項目の移行規則と説明が別途必要であり、現行にその項目があるとは扱わない。

## B：配当と株価・調達評価を結ぶ

### 設定だけで高評価を得る操作

現在の配当性向は同じ週に変更でき、支払は週終了まで起きない。もし設定値だけで株価や調達評価が上がると、「高配当に設定→高い評価で増資→配当 0% に戻す」で実際には配当を払わず評価だけ得られる。増資には持分低下と 5% 控除があるため、これを即「無限・無損失」とは呼べないが、配当という対価が空振りする設計上の抜け道になる。

評価へ使うなら、少なくとも宣言した配当率と実際に支払った履歴を分ける必要がある。評価の幅を制限するだけでは、未払いの設定変更が有利になる問題は解決しない。操作の履歴を持つ期間、低利益週や未払いの扱い、いつ評価へ反映するかが仕様となる。

### 配当・評価・増資の循環

現行評価には会社現金が含まれる。会社全体へ配当実績の倍率を掛けると、事業が増えていなくても、増資で入った現金が次回評価でさらに倍率を受ける。そこからまた増資する経路は、単に倍率へ上限を付けただけで健全と判断できない。

また、配当で会社から D が出た分を評価の基礎で減らさず、配当評価だけ上げるなら二重の押上げになる。配当後の現金を反映した基礎評価と、追加する投資家評価を別々に説明できなければ採用しない。将来、自社株買い・創業者の持分回復まで足す場合は、持分下限という現行の有限性も崩れるため、増資と買戻しの一周全体を再検証する必要がある。

実支払履歴を使っても、配当による現金流出より評価上昇から得る資金の方が大きければ「配当してから調達」が固定の手順になりうる。逆に上昇が小さすぎれば配当 0% の優位を残したまま表示が複雑になる。狭い数値調整で両案を見かけ上同じにするより、そもそもプレイヤーにどの異なる目的を渡すかを先に決めるべきである。

配当をしないと罰・強制解任・必須進行の閉鎖を与える案は、自由な再投資の選択を消すため今回の推薦に含めない。B は一般に経営ゲームへ不要という主張ではなく、このゲームの現在の評価・反復可能な調達操作へ接続するには検討範囲が広いという判断である。

## C：現状の合理策として正確に説明する

0% が会社の成長資金を残す目的に有利と表示し、個人資産や株主の反応を実装済みのように説明しない。現在の資本比較・IPO の結果表示はこの立場に整合する。UI が正直になる利点はあるが、配当の選択理由や持分の意味が増えるわけではない。C を経済分岐の完成とは報告しない。

## 将来の受入条件

本レビューでは新しい経済を実装・シミュレーションしていない。次を、A/B を具体化した場合に初めて検証する候補とする。

1. **元帳が一致する。** 同一決算について会社配当出金＝創業者入金＋外部支払。q の上下限、円未満の端数、利益 0・赤字、配当 0 でも一致し、予測・画面再表示・保存再試行では増えない。
2. **敗北条件を変えない。** 個人に十分な資金があっても、借入があり N≤0 なら敗北。N>0 でも会社の週末現金<0なら既存の資金不足条件を適用。個人資産は完遂の新しい必須条件にしない。
3. **順序の抜け道を測る。** 同週の配当率変更→増資→配当率復帰、複数回増資、週末の配当実行、保存・復元の組合せで、事業利益・会社資金・個人資金・外部出資・外部配当・手数料・持分を分離して追う。現行の持分制約を越えた無限性を想定せず、実装された操作で検証する。
4. **異なる目的を説明できる。** 全取得を急ぐ無配方針を許しつつ、任意の個人目標を選んだ人が配当を出す理由を言えるか。全取得前の配当が不利なら、その結果を設計の限界として残す。数値を受け取る回数だけを楽しさの証拠にしない。

相互批評では rail 担当へ、A の資産の二重計上・配分の丸め・会社への自動還流を避けること、B の宣言だけを評価する抜け道、会社全取得目的に対する A の限界を直接伝えた。現行 C、次の最小候補 A、B は後段という順を推薦するが、将来の実装決定や検証完了を意味しない。
