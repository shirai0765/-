# 0.4.2 店舗予測の会計・説明レビュー

2026-10-06。資本担当による独立レビュー。対象は `src/sim/engine.ts` の `getStoreOperatingInsight` と共通計算、`src/ui/StoreOperatingInsightPanel.tsx`、既存の `managerPlan`・全社週次決算。[表示の受入方針](store-insight.md)と[カフェ企業の公開決算調査](../research/cafe-economics.md)を参照した。**会計上の必須修正は発見していない。経済係数の変更や、人間の理解の確認を行ったという結論ではない。**

この担当はコードを編集していない。読み取りレビューに加え、`/tmp/store-insight-accounting-check.ts` で独立照合し、結果を `/tmp/store-insight-accounting-check.json` に保存した。API 担当の[変更前後 29 状態の一致記録](../store-insight-api-verification.json)は別の検証であり、以下の独立 6 状態と合算して独立標本数を主張しない。

## 検算した会計境界

| 対象 | 確認結果 | 表示で維持する意味 |
| --- | --- | --- |
| 店舗利益 | `previewWeek(...).storeResults` の同一店舗の 5 項目と一致 | この店の営業による予測。本部費・利息・元本・配当控除後の現金ではない |
| 費用 7 項目 | 材料、履行、人件費、賃料、店舗設備、広告、店長費を元計算の値から返す | 新規の費用を加えず、従来の利益の理由を説明する |
| 円丸め | 売上 − 個別円丸め費用合計 − `roundedCostAdjustment` ＝ 店舗利益 | 費用側の調整額。負なら個別丸め費用を減らす。追加支払いではない |
| 自用物件 | 店舗賃料は 0、物件維持費は従来どおり全社側 | 「家賃 0」と「場所に関する費用が一切ない」を区別する |
| 店長の実効設定 | `managerPlan` の今週の設定と一致。入力設定と別オブジェクト | 入力値をそのまま使った予測ではない場合がある |
| 配分枠 | 元の入力人数 × 基準人件費 52,000 円 ＋ 入力広告費 | 実給与・店長費を含む支払上限ではない。景況による賃金倍率を枠の計算には使わない |
| 信用 | API は現在の全社信用だけを返し、将来値は追加しない | 全店満足の単純平均と全社利息後利益の正負で週末更新。単店の満足改善から上昇を保証しない |
| 状態保持 | API の前後で状態の JSON が一致。返却設定・結果を破壊的に変更しても元状態は不変。不明 ID は `null` | 表示・展開・選択で資金や保存値を動かさない |

店舗維持費は現行の `28,000 × level` という運営費であり、今回の API が新たに減価償却会計を導入したわけではない。開業費や設備増強の支出をこの費用表へ追加で引いたり、IR のリース返済を店舗家賃へ足したりしない。

## 独立実例

seed 812、センター街 `center-01`・標準店を公開 `openStore` で開業。通常の `advanceWeek` で 40 週目まで進め、店長は公開 `updateStore` で切り替えた。自用物件の確認だけは資金不足を回避するため購入前の会社現金を **試験専用の 9 億円** に置き換えてから公開 `buyProperty` を実行した。この例を通常プレイの到達性や採算の証拠にはしない。

| 状態 | 確認した値 |
| --- | --- |
| 開業直後 | 売上 649,600 円、店舗利益 53,528 円、1,120 人、満足 58 |
| 第 8 週・端数あり | 店舗利益 50,106 円、費用の丸め調整 −1 円。個別円丸めを足すだけでは一致せず、調整後に一致 |
| 第 40 週・委任なし | 店舗利益 43,066 円。賃金倍率約 1.04275、実人件費約 216,892.049 円、賃料約 111,570.183 円 |
| 第 40 週・店長あり | 入力は価格 580 円／4 人／品質 65／広告 10,000 円、実効は 754 円／4 人／品質 55／広告 0 円。店舗利益 210,086 円、店長費約 75,078.017 円 |
| 第 40 週・別の店長入力 | 価格 1,000 円／8 人／品質 85／広告 30,000 円を入力。基準配分枠 446,000 円に対し、実給与＋広告は約 463,784.097 円、さらに店長費約 75,078.017 円。実支払上限との区別が必要 |
| 第 40 週・自用物件 | 店舗賃料 0 円、店舗利益 321,657 円、全社営業利益 314,503 円。差は全社側の物件維持費で、店舗費用へ再度引かない。費用の丸め調整 −1 円 |

以上の 6 状態で店舗結果、費用調整、実効設定、元状態不変、返却値の独立を照合した。金額表示は円に丸め、内部計算を丸めた費用の合計へ置き換えない。全状態・全週を網羅した証明ではない。

## Panel と既存入力の説明

Panel は店舗利益と需要の説明を先に置き、予想満足を常時表示する。需要は「見込み」、能力は「対応上限」、客数は「迎えられる予想人数」と区別し、需要との差を実測の待ち客や確実な逸失売上へ換算しない。表示人数が同じ場合は上限付近という説明になり、丸めによる 0 人の不足を強調しない。

費用内訳の読取では、7 科目、丸め調整、費用合計が同じ会計範囲になっている。調整には「追加の支払いではありません」、自用物件には「維持費は全社の収支で別に差し引く」という説明がある。店長案には実効設定と別建ての店長費、詳細には基準配分枠と実際の支払額の違いがある。単店満足で会社信用の上昇が決まらない旨も明記されている。会計上の必須修正はない。

既存 `storeControls` の「予算内で調整」は支払上限と誤読されるため、App 担当へ「入力した人員・広告の配分枠で調整」への最小変更を提案した。細かい基準人件費の式は Panel 詳細へ置き、入力欄の常時説明を長くしない。今週の予測と前週実績の表示を混ぜず、既存の借入利益不足・週末現金不足の全社警告は別に維持する。

## IR との対応と残る確認

カフェ IR は、直営と FC 本部、店舗と連結、運営費と純粋な給与、費用と設備・リース支払を分ける根拠として使った。3 社の利益率や原価率を、本作の一店舗へ直接採用したわけではない。品質・価格・人員の係数を現実の報告書が裏付けたとも扱わない。

このレビューは API の実行と Panel のコード読取であり、ブラウザ上の 390px 表示、App 接続後の店舗切替、前週との時点表示、全社警告との併存は UI QA 担当が確認する。人間が「次に何を変えるか、その理由」を理解できるかは観察が必要で、自動一致検査では代用しない。
