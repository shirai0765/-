# 経営分岐の設計レビュー — v0.3.1

2026-10-07。分岐担当。エンジン・画面・保存契約・既存キャンペーン報告を読んだ設計案。以下の「現行」以外は未実装で、数値案は調整仮説。設計レビュー後にv0.3.1配布基点が保存され、新規出店の比較UIだけ実装許可を受けた。配布済みZIPや都市モデルは変更対象外。

## 判断

まず、既にある選択の理由と結果をつなぐ。後半の件数や強制待機を増やす前に、選ぶ前の全社増分、支払後資金、引継ぎ費用、選んだ後の実績を見えるようにする。現行の全取得目標では「非上場」「配当を出す」「持分を高く保つ」を同等に成立する勝ち筋とは呼べない。

借入残高がある週の営業利益−利息が0以下なら、その週に倒産する要件を維持する。現金、資産売却、受取配当、週末の元本完済でこの条件を回避しない。自動進行の事前停止は救済ではなく、プレイヤーに営業前の再判断を返す仕組みとする。

## 分岐を成立させる次段の仕様候補

### 調達: 同じ投資案件に三つの資金計画

案件を選んだとき「現金で実行／借入を足して実行／上場・増資を使って実行／今回は保留」を同じ表で比較する。実行不可案も不足条件を表示する。各案の必要調達額は案件費とプレイヤー指定の現金留保額から求め、借入・増資の現行上限を適用する。資金計画を表示しただけで取引しない。

表示は、実行直後現金、今週利息後利益、元本返済、週末現金、創業者持分、引継ぎ中の毎週費用。現在の `applyAction` を複製状態に順番に適用し、その結果へ `previewWeek` を使う。融資だけの予測と、融資後に目標案件へ支出した予測を混ぜない。今週の確定予測以外の将来は幅・仮定で示す。

内部留保が有利なのは既存資金で間に合う、または準備費で借入利益条件を割る状況。借入は持分を保ちつつ今の機会を取る場合。増資は準備中負担が大きく、返済を背負いたくない場合。これらは条件付きの利点で、全案を等しくおすすめする約束ではない。

長期には持分を維持する意味が必要。ただし現段階で上場罰金・配当義務・強制待機を追加して資金不足を作らない。将来の統治を作るなら、失う裁量と株主側から得る支援を事前に提示する。同じ全取得目的のまま配当に記念バッジだけ付けても、経営上0%が強い問題は解消しない。

### 店舗: 利益、満足、投資額の前提を公開する

同一立地で価格・品質・人員・広告・店長を含む案を比較する。「初期費用を抑える」「現在の全社利益を伸ばす」「満足度を保つ」を目的として説明し、同じ案が全項目を上回るときは無理に3候補へ水増ししない。

能力上限の店で広告を増やす案、需要不足の店で設備を増やす案には、支払額と全社増分がそのまま見える必要がある。成功時は来店・満足・利益と店舗外観の成長が対応する。既存のスタイル変更80万円、設備増強120万円×現Lvを使い、無料で何度も有利な形態へ切替える別仕様は作らない。

将来の企業方針案は、店長1人を配置すると解禁される「利益優先／接客重視／価格の安定」。追加の一律利益ボーナスではなく探索制約にする。仮仕様では現行満足65下限、接客重視85下限、価格安定はプレイヤーが選んだ価格上限を守る。人員・広告予算は共通、満たせないときは実行不能の理由を返す。切替そのものは無料、各週の実運営費が代償。これは店長の選び方を増やす案であり、現行の方針機能ではない。満足重視が意味を持つのは信用条件が残っている間で、後半にも必要なら別の顧客価値モデルを先に設計する。

### 不動産・鉄道: 会社名が変わる先の選択

現行の地区用途を、地図の所有構成と同じ画面で比較する。商業は処理能力に余地がある自社店、賃貸は外部賃貸が多い地区で利益が出やすい。保有構成が変わった後にも最初の選択を振り返れるよう、工事名と効果内訳を残す。

鉄道の後続企画は「初鉄道＋対象地区物件」を入口に、保留を含む沿線企画を選ばせる。仮案: 回遊改善は初期1,200万円・6週・維持週2万円でその地区のカフェ需要+5%。賃貸接続は初期1,800万円・8週・維持週1.2万円で外部賃料+4%。同地区で一つ、既存効果と合計上限を共有し、満席・自用だけなら無理に着工させない。これは未検証の起点であり、現在の経済へそのまま追加する数値ではない。交通の見た目と数式は同じ選択IDに結び付ける。

鉄道が全取得の終盤まで後回しになる現状を、価格を下げるだけで直さない。低収益でも早めに沿線の独自体験を始めたい経路と、小型事業を積んでから鉄道に進む経路を比較する。これで前者が成立するかは公開操作の別キャンペーンが必要。

### 営業提案: 調べるかどうかも判断にする

公開情報だけで全期間の保守的収支が十分悪い案件は、調査せず見送れる。計算は `効果×(契約週−導入待ち)−週額費×契約週−初期費＋残価` を基準にし、調査済みなら調査費も総投資に含める。残価は現金回収で営業利益ではない。途中解約はその時点の残期間、残価、解約料で別評価する。

幅が判断をまたぐ案件では調査に価値がある。現在のカタログは1.5万円、不動産9万円で幅を絞る。調査しても契約しない結果を失敗扱いしない。効果の平均値を知るためだけに全件調査させない。

後続で実店舗適性を導入する場合、例えば処理能力が不足する店があるとPOS候補、3店舗以上で共同仕入れ候補を解禁する。効率効果と導入費・運用費・研修による減収を同じ予測に反映し、同じ種類の併用不可を維持する。初期費用と不確実性があるため「無料診断して全部契約」が常勝にならない設計を実測する。最初から悪条件と決まった営業を毎回断るだけの反復にも戻さない。

## 3名の議論と修正

1. 成長担当は初期に2〜3候補を並べる案を提示。分岐担当は、同等に推奨すると未検証の劣位案へ誘導するため反対した。合意は「利益・投資額・満足など前提を明示し、実際に同じ候補なら候補数を減らす」。選択肢の数を成果指標にしない。
2. 分岐担当は調達比較を最初の実装に提案。ペース担当は、大型投資には効くが初回の経営実感への寄与は弱いと指摘。成長担当の「同週の予測前後→保存済み決算で結果を読む」を最初に置き、その次に調達比較を載せる順に修正した。
3. 取得二方式の新イベント案より共通の成果記録を優先。市場買収画面が既に前後比較を持つため、同じ確認画面の増設はしない。上場の罰や待ち時間を増やして分岐を作る案は採らない。
4. 持分維持には将来の経営裁量を結び付ける方がよいとの意見で一致したが、初期体験の小実装には入れない。配当の支配性を外見だけで隠さない。

## 凍結解除後の最小コード範囲

最終合意は「新規出店だけ」に絞った、同週の比較と最初の決算結果。初店と2号店に同じ流れを使う。委任・設備増強・IPO・買収の履歴まで同時には作らない。既存の出店予測と重複する別ダッシュボードは作らない。

実装範囲は自己資金による3形態の比較のみ。資金不足なら実行不可理由と既存の財務画面への導線を出す。議論した「不足額を借りて出店」は今回採用しない。融資や増資を自動で足さない。現金が開店費ちょうどでも週末現金不足は別に警告する。

- 変更前状態と変更後状態を同じ週で予測し、全社利益差と手元資金差を示す。店舗単体利益を全社増分と表示しない。
- 実際に保存できた決算を結果に使用する。「あなたの設備投資で利益がこの額増えた」と断定せず、同週予測との差と決算週の全社実績を区別する。他の操作・景況・既存店の変化が混ざるため。
- 初店・店長・設備Lvなど既存状態から復元できる事実は派生表示する。保存していない過去の価格・予測・選んだ理由を現在値から作らない。完全な判断履歴を保存するなら別の明示的な保存仕様と検証を設ける。
- 次の操作は価格見直し、委任、別の出店候補へ戻る既存導線。結果カードを見るための追加確認や、同じ成功の繰返し表示を増やさない。

第二候補が上記の同案件の調達比較。新経済・新乱数・報酬通貨・本格統治・沿線利益は別スライス。

担当実装: `src/sim/storePlanning.ts` と `src/ui/StoreOpeningPanel.tsx`、専用CSS。実際の `applyAction(openStore)` 後に予測するため、借入併用の仮状態を作らない。2026-10-07時点で専用5テストが成功。画面組込み・保存結果記録・ブラウザQAは他担当と統合して別途検証する。

## 受入基準

1. 予測表示は現在の `applyAction` + `previewWeek` に一致し、表示を開くだけで状態・乱数・現金・保存を変えない。
2. 借入ありで利息後利益が0または負なら、残現金が十分でも破綻警告が出る。元本返済は利益と二重計上せず、別に現金不足も示す。現行の判定を弱めない。
3. 店長なし4店目、既存近隣店との競合、設備投資後の需要不足を含む条件で、単体黒字でも全社増分が悪い例を隠さない。表示と実際の操作後予測が一致する。
4. 市場取得の引継ぎ中は収益を先取りせず、準備費と保有株精算を反映する。独立・統合のどちらも有利になる条件を別々に実測する。両方が存在しなければ設計課題として報告し、単に選べたことを合格にしない。
5. 保存失敗した決算は成果に載せない。読込で同じ成果を水増ししない。過去データのない既存保存で不明値を捏造しない。
6. 3人以上の短い観察で、各人が少なくとも一つ「なぜこの案を選び、何を諦め、結果どうだったか」を自分の言葉で説明できるかを見る。全員が同じ案でもそれだけで失敗ではない。前提を変えても理由なく同じボタンを押す場合は分岐を再検討する。
7. 自動キャンペーン922〜1,006週・324〜332操作は既存の到達証拠に限定する。新しい分岐を楽しめた時間、280判断、30時間の実プレイ達成と読み替えない。本レビュー中は重いテストやブラウザQAを実行していない。
