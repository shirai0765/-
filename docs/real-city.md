# 実際の渋谷の3Dモデル

2026年10月7日（日本時間）、公式PLATEAUカタログと配信アセットへの再接続に成功しました。以前の403失敗は過去の通信設定での記録です。今回は `public/models/real-shibuya/manifest.json` の `status: downloaded` と取得レスポンスのSHA256・バイト数で実取得を記録しています。

採用データは `13113_bldg_lod2`「建築物モデル（渋谷区）」、2025年度公開、LOD2、`texture: true`。国土交通省公式カタログのフィールドを実際に読み取った値です。公開年度と個々の写真撮影日・現況は同一ではありません。

`real-shibuya.html` は実データ用の独立したビューアです。建物の位置とテクスチャは取得した実データから読み込みます。交差点・109周辺・全景の視点切り替えがあります。経営ゲームの圧縮された創作街区とは別の座標空間であり、経営マップそのものを実測地図へ置換したわけではありません。

## 取得と検証

```sh
python3 scripts/research-plateau.py --max-mb 80
python3 scripts/smoke-real-city.py
```

取得通信量はカタログを含め81,671,690バイト（80MiB以内）。33個のb3dmに33個の画像が埋め込まれ、外部画像・バッファ参照はありません。全LODを合算した282,033三角形には重複する粗い親LODが含まれます。独立ビューアでは `REPLACE` 階層の末端20タイルだけを読み込み、親LODとの重複表示を避けます。

対象は交差点 `[139.7006, 35.6595]` 周辺の約550m四方と交差する完全なタイルです。個々の建物を550m境界で切断していないため表示範囲は広がります。親LODには新宿等の遠方建物も含まれますが、末端ビューアはそれらの親LODを表示しません。

GLBは `KHR_draco_mesh_compression`、`EXT_texture_webp`、`CESIUM_RTC` を使用。付属のThree.js用Dracoデコーダーで復号し、GLTFのY-upから3D TilesのZ-upへ回転、RTCの地心直交座標オフセットと祖先transformを適用してから、交差点を原点とするローカル東・上・南座標へ変換します。基準楕円体高度は50m。境界検証は回転後のAABBの過大評価を避け、頂点を使う精密Box3で行います。

テクスチャは撮影時の陰影を含みます。元データの金属度0.5による過度の暗化を避けるため、ビューア側で非金属・高粗さにして表示しています。写真そのものの色や描かれた広告を書き換えていません。

## 範囲と限界

PLATEAU部分は建物モデルです。地表には国土地理院のシームレス空中写真を追加し、実際の道路・横断歩道・鉄道の位置や色を表示します。写真は最も低い建物の足元に置いた平面へ地理座標で配置しており、渋谷の起伏を再現していません。標高の高い場所では建物の足元と平面に隙間が生じます。樹木や歩行者の立体形状は追加していません。建物ごとに写真解像度や撮影時期が異なり、109の広告や現況が最新とは限りません。LOD2は外形と写真テクスチャのモデルで、窓や店内のすべてが立体形状として作られているわけではありません。

## 実際の街路写真

`python3 scripts/research-ground.py` で国土地理院の `seamlessphoto` XYZタイルを取得。ズーム18、72タイル、合計1,387,748バイト、約0.5m/画素です。JPEGは加工せず保管し、Web Mercatorのタイル境界をWGS84経緯度からローカルENUへ変換して配置します。写真の撮影日はモザイクの場所ごとに異なり、PLATEAUの2025年度公開と一致するとは限りません。

`public/models/real-shibuya-ground/manifest.json` に取得URL・SHA256・バイト数・各タイル境界を記録。`src/realcity/Ground.ts` の表示コストは144三角形、72描画呼び出しです。DEMは使用していません。標高データの標高基準と楕円体高の差を未検証のまま混ぜないため、地面は明示的に平面近似としています。

出典表示：**地理院タイル（シームレス空中写真）を使用**。[地理院タイル一覧・当該レイヤー](https://maps.gsi.go.jp/development/ichiran.html#seamlessphoto)、[国土地理院コンテンツ利用規約](https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html)。

## 編集可能なモデルの書き出し

```sh
python3 scripts/export-real-city.py
blender --background --python scripts/prepare-real-blender.py
```

公式建物20末端タイルと地表写真72タイルだけを `real-shibuya.glb` へ書き出します。カメラ・UI・補助の灰色平面・経営マップは含めません。出典・加工内容・座標原点・平面地面の制約をモデルのメタデータに記録。書き出し後にGLBをブラウザへ再読込し、元の建物境界と5cm未満の差、地表72メッシュ、画像の埋め込み、外部URIがないことを確認します。検証結果は `real-shibuya-glb-qa.json`。

Blender版はGLBをインポートし、画像をパックして `real-shibuya.blend` として保存します。GLBはY-up、Blenderは標準のZ-upへインポータが変換します。いずれもメートル単位で、測量データを再度圧縮したゲーム縮尺ではありません。

GLBの画像包装では、書き出しPNGをRGBA画素ハッシュで元のWebPアトラスと照合し、一致した場合は元バイト列を再使用します。その他は可逆WebPに再符号化し、全画像でRGBA画素が完全に一致することを検証します。画像の拡大やAI補完は行いません。ビューアには建物の明るさ調整（1.0–1.8、初期1.15）がありますが、元画像は変更しません。

## 単一HTMLのオフライン版

`node scripts/package-real-city.mjs` は `/workspace/shared/shibuya-artifacts/real-shibuya-viewer.html` を生成します。末端の建物20タイル、ズーム18の地表写真72タイル、取得記録、Draco WASMとラッパー、Three.js、CSS、ライセンスを内包します。99ファイル相当、83,235,002バイト（約83.2MB、79.4MiB）。使わない親LODと旧ズーム17地表画像は含めません。

`src/realcity/assets.ts` が必要な埋め込みデータだけをBlob URLへ変換します。通常の開発ビューアでは従来のローカルURLをそのまま使い、グローバルfetchは変更しません。ファイルを直接開く運用を想定し、検証環境では同じHTMLを内部HTTPで配信して、初回HTML以外の全HTTPリクエストを禁止した状態で表示を確認します。出典リンクを利用者がクリックした場合だけ外部サイトへ移動します。

最終検証記録は `real-shibuya-offline-qa.json`。建物20タイル・地表72画像、座標境界、3視点、マウスホイール、取得記録のBlobリンク、建物の明るさスライダーを確認し、初回HTMLだけのHTTPリクエスト1件、外部アセット通信0件、コンソールエラー0件を検証します。建物の初期露出は1.15で、1.0〜1.8に調整できます。元写真の画素は加工せず、地表写真はtoneMapped=falseで建物の露出変更の影響を受けません。
