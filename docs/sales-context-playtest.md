# 営業提案の適性・保存・警告：DOMプレイテスト

`scripts/smoke-sales-context.py` を実Chromiumで実行し、7項目が成功。営業画面の調査・契約・決算・保存・再読込を確認した。ソースの経済処理や画面は変更していない。

## 実行条件

- Vite開発サーバーへPlaywrightで接続。Chromiumは `--disable-gpu`、`/src/city/CityView.tsx` の応答だけを `return null` のモジュールに置換した。都市3Dの描画検証ではない。
- デスクトップ1280×960、モバイル390×844。document・main-area・各提案カードの横はみ出しを検査した。
- v3の初期データはseed 42・初期資金1,200万円から `createGame`、公開 `openStore` / `updateStore` / `settings`、12回の `advanceWeek` で準備。初期資金・信用・週数・利益の直接書換えはない。開業から13週までの準備はエンジン操作で、その後の調査・契約・4回の週末進行は実UI操作。
- v1は通常の初店開業直後。v2だけは互換表示専用に旧canonical提案を差し込むfixtureであり、現行カタログから通常発生した案件とは扱わない。旧条件の同一性は別の84ケース回帰でも確認済み。

```sh
python3 scripts/smoke-sales-context.py
```

接続先は `PLAYTEST_URL`、成果物先は `SALES_CONTEXT_OUT` で変更可能。既定の成果物先は `/workspace/shared/shibuya-artifacts/sales-context-v4`。この実行の `result.json`、保存fixture、画面画像を保持している。

## 確認結果

| 項目 | 実際に確認した内容 |
|---|---|
| 旧v1 | 入門2提案が表示され、初期費8万円など旧条件を維持。新しい店舗適性の事実を付け足さない。表示・明示保存だけではデータが変化しない |
| 調査前のv3 | 第13週・1店舗、直近第12週の客数1,210人を表示。待ち時間などは「未計測」。初期24万円＋週1.1万円×26週＝固定費52.6万円、3週の待機込みの純収支幅が有料調査前から見える |
| 調査 | モバイルの実ボタンで15,000円を1回だけ支払う。元の信号・固定前提を保持し、週次効果を15,319〜28,919円へ絞る。支払済み調査費を含む全期間純収支は−188,663〜124,137円。二重調査ボタンは残らない |
| 契約・決算・再読込 | 初期24万円を1回支払い、第13〜16週を実UIで決算。毎週の現金差は保存済み決算と一致。効果判明前に実現値は出ず、第16週に17,760円を記録。累積週額費44,000円、累積効果17,760円。第17週の再読込で保存データ全体が完全一致 |
| 旧v2 | POSの旧5,000〜39,000円幅を表示し、新しい店舗前提を捏造しない。旧canonical fixtureの表示・明示保存後も全保存データが一致 |
| 借入中の警告 | 通常の10万円借入と店舗設定から、契約前の利息後利益823円、契約後−10,177円の状態を作成。契約確認と週次計画の警告が一致。実際に営業すると現金11,394,186円が残っていても借入利益条件で倒産し、決算利益も−10,177円で一致 |
| ブラウザ | console error・未処理例外0件。390pxでdocument・本体・提案カードに横はみ出しなし |

借入なしの契約確認では借入利益条件の追加警告が出ないことも検査した。資金が多ければ借入中の営業赤字を救える、という誤った案内になっていない。
