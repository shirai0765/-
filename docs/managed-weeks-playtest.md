# 連続営業のブラウザ結合検証

2026-10-07、Chromiumで実際の画面を操作して確認しました。実行コマンド：

```sh
python3 scripts/smoke-managed-weeks.py
```

Viteの既定URLは `http://127.0.0.1:5173`。`PLAYTEST_URL` と `PLAYTEST_OUT` で接続先・証跡先を変更できます。

## 確認した流れ

1. 初期資金1,200万円の新規会社から公開エンジン操作で1店舗を開業し、店長を配置して12週営業。12週の黒字を実際に達成した第13週の会社データを、画面のファイル読み込みから導入しました。資金・黒字回数・週の直接改変はしていません。
2. 営業計画の期間選択で4週を指定して実行。第14〜17週のバックアップが全て存在し、週報4行の営業週、最終状態、期間の現金増減が通常週次計算と完全一致しました。
3. 続いて13週を指定。第25週に新しい営業提案が現れたため8週で停止しました。停止理由が画面に表示され、週報8行と合計現金増減が一致。保持されるバックアップは第14〜25週の12件でした。
4. 設定画面からセーブJSONを実際にダウンロード。チェックサム検証後の状態が連続営業後の会社と完全一致しました。
5. ページを再読み込みして「続ける」を押し、第25週の完全な状態が維持されていることを確認。コンソールエラー・ページ実行エラーは0件でした。

## 証跡

既定の出力先 `/tmp/shibuya-managed-playtest/`：

- `managed-results.json` — 確認結果と最終週・現金・バックアップ週
- `managed-four.png` — 4週営業の結果画面
- `managed-opportunity.png` — 新規提案で停止した結果画面
- `managed-fixture.json` — 実際の営業で生成した導入データ
- `managed-export.json` — UIからダウンロードした最終セーブ

描画負荷を抑えるため軽量品質を設定し、導入後は店舗経営画面で検証しました。この試験は連続営業UI・週次保存・停止・合計表示・書き出し・再開の結合検証であり、3D画質の評価は別の試験です。保存失敗・途中キャンセル・破綻予測・IPO停止は `tests/managed-weeks.test.ts` で検証しています。
