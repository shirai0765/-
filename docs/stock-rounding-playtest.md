# 0.4.2 株式注文の円未満処理 — 実UI検証

2026-10-06。購入代金を切り上げ、売却代金を切り捨てる変更のための検証記録。既存の店舗計算・保存同値性の記録を上書きせず、**株式取引の端数は意図的に経済結果を修正する別の変更**として扱う。

従来の四捨五入では、株価1,584.5円の2株を3,169円で買い、1株1,585円で2回売ると、週や価格を変えずに1円増やせた。新仕様では購入3,169円、分割売却1,584円ずつとなり、差額は−1円となる。これは値上がりや運用成果ではなく、円単位の決済規則の確認である。

## 準備した検証

[scripts/smoke-stock-rounding-v042.py](../scripts/smoke-stock-rounding-v042.py) はCityViewを明示的なブラウザroute stubへ置き換え、GPUを使わず実際のAppと市場注文画面を操作する。株価・代金の期待値はゲームのヘルパーを呼び出さず、Python `Decimal` で独立計算する。

| 経路 | 条件 | 確認対象 |
|---|---|---|
| 通常新会社・9005 | 初期株価1,584.5円、2株購入→1株売却→1株売却 | 小数株価表示、各注文の総額と実行後現金、週が進まないこと、保有がなくなり現金−1円 |
| 通常新会社・9432 | 初期株価170.1円、2株購入→1株売却→1株売却 | 購入341円、売却170円ずつ、同じく現金−1円。購入と売却で丸め方が違う境界 |
| 保存・再開 | 両方を初期1,200万円から実行 | 最終11,999,998円・保有0。各実行は`applyAction`の全stateと一致し、明示保存後のreloadでそのまま再開 |
| 9005の1円不足 | `createGame`で作った会社の現金だけ1,584円へ設定して保存ファイルとしてimport | 1株購入に1,585円必要。実行ボタン無効、資金不足理由、エンジンも拒否しstate不変 |
| 9432の1円不足 | 同様に現金だけ170円へ設定 | 1株購入に171円必要。UI・エンジン・保存で同じ境界 |
| 安全整数域外の旧保存 | 現金だけ`2**54`へ設定した読み込み可能な合成save | 読み込み可能でも株の買付は警告付きで無効。エンジンも拒否し、少額の購入が現金から消えない精度問題を起こさない |
| 表示と無変更 | 注文を開き株数を変える・閉じる | 比較だけで現金/週/保存を変更しない。デスクトップと390pxで注文内容が横にはみ出さない |

不足額の2例と安全整数域外の残高は境界検証の合成fixtureであり、通常プレイでその残高へ到達した証拠ではない。通常の往復取引には資金・株価・週の注入を使わない。例示2銘柄の成功を、全株価・全分割パターンや投資全般の安全性の証明とはしない。既存の小数現金の互換挙動はエンジン担当の別検証に委ね、この通常整数残高の往復と混ぜない。

## 実行状態

`python3 scripts/smoke-stock-rounding-v042.py` を統合後に実行し、7カテゴリが通過した。ブラウザconsole/page errorは0。通常経路の6件の注文は、独立Decimal期待値・表示総額・現金変化・エンジンの全stateが一致した。

| 銘柄 | 2株購入 | 1株売却 × 2 | 往復の現金差 |
|---|---:|---:|---:|
| 9432 | 341円 | 170円 × 2 | −1円 |
| 9005 | 3,169円 | 1,584円 × 2 | −1円 |

通常会社は週を進めず両取引を終え、現金11,999,998円・保有0で保存し、そのstateのまま再開した。株価170.1円と1,584.5円を端数込みで表示し、「購入時に切り上げ、売却時に切り捨て」の説明を注文画面内で確認した。

1円不足の両ケースは、現在現金と必要額を正しく表示し、実行を無効化した。取引後現金は不可能な負残高を見積るのではなく「取引できません」と表示する。エンジンも拒否し、操作前後の保存状態は一致。安全整数域外の旧saveも読み込めるが、同じく警告付きで取引できず、状態を壊さない。両境界で「手元資金で買える」の絞込みに入らないことも検査対象にした。

最初の試行では、準備時のスクリプトが不足注文の取引後現金を`¥-1`と期待して停止した。統合された共通cash guardは決済不能を返すため、実装の契約に沿って「取引できません」・現在現金・購入総額・不足警告・実行無効を照合するよう修正した。金額不足の検査は残しており、実装上の不具合を除外したものではない。

結果は `/workspace/shared/shibuya-artifacts/stock-rounding-v042/result.json`。各注文の前後現金と約定額、境界拒否のエラーメッセージを収録した。同フォルダの `9432-buy.png`、`9005-sell.png`、`9432-one-yen-short-mobile.png`、`unsafe-cash-warning-mobile.png` を目視し、小数株価・丸め説明・資金不足・範囲外警告が読めることを確認した。注文dialog/documentの横はみ出し検査も通過。都市描画はstubなので、これらを3Dの証拠にはしない。

## 既存の店舗同値性証拠との関係

[店舗因果UIの設計と同値性検証](design/store-insight.md)では、読み取りAPIの抽出後・株式端数修正前のengineを識別するSHAとともに、29状態と既存店舗研究の完全一致を記録した。この過去の検証結果は保持する。今回の端数修正後に株式注文の現金や取得原価が変わることは、店舗係数を変えたことも、過去の記録が誤っていたことも意味しない。

新しい版の評価では「店舗の営業計算は維持」「市場の円未満決済は裁定を防ぐため変更」を分ける。保存schemaの変更や既存株価の丸め直しは、このUI検証の目的に含めない。人間の理解・面白さ、実際の市場での運用成果も検証していない。
