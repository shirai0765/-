# 駅まち共同開発の街並み

`src/city/RailProjectVisuals.ts` は既存の渋谷風駅の外側に、小さな共同開発広場を追加します。メインマップは圧縮した創作街区です。新しい出入口・看板・売店も独自の意匠で、実際の渋谷駅施設の測量モデルではありません。実景 PLATEAU ビューアーとは別の表示です。既存の109・カフェ GLB、駅本体、線路は変更しません。

| 地区の共同事業 | 中心 x / z | 正面 |
| --- | --- | --- |
| センター街 | 58.3 / 22 | 西 |
| 道玄坂 | 58.3 / 43 | 西 |
| 宮下・東口 | 92 / 25 | 東 |
| 桜丘 | 58.3 / 65 | 西 |

各広場は13 × 7.4 m。西側は明治通り車道端 x=52 と駅西端 x=62.65 の間に配置し、歩行帯を残しています。西側最外端は x=54.6、駅側端は x=62.0。既存の地区開発が各物件の脇に設置する照明・植栽とは離れた場所です。

商業案は細い柱で支える白い折板屋根、木ルーバー、売店、植栽付きベンチ、行先案内を備えた回遊広場です。賃貸案は同じ駅前空間に、落ち着いた木枠の管理窓口・郵便受け・宅配ロッカー・屋根付き駐輪ラックを整備します。新しい高層ビルを増やさず、用途を地上階の違いで表現します。

工事中は骨組み、仮囲い、資材と日本語の工事看板を表示します。運営休止中も完成済みの建築は残り、案内が「連携休止中」に変わります。工事中に物件を手放した場合は、完成週までは仮囲いを残します。完成後は休止状態の完成建築になります。経済側の `getRailProjects` と同じ状態を参照します。

`new RailProjectVisuals(parent)` を一度作成し、React の状態更新で `update(state)` を呼びます。地区・選択案・状態・完成フラグが変わったときだけ、一つの子グループを作り直します。同じ状態で週を進めてもジオメトリは再生成しません。全地区の小部品を `CityArt.batch` で色別にインスタンシングし、看板も既存の CanvasTexture 方式を使います。交換前のジオメトリ・マテリアル・テクスチャは `disposeScene` で破棄します。

「沿線を見る」用に `RAIL_PROJECT_VIEWPOINTS[districtId]` から `position` と `target` の3要素タプルを取得できます。通常の画角36度で4地区とも実際に描画・目視確認済みです。西側3地区は車道上空の高さ8.9〜9.3mから広場正面へ、東側は高層建物の北側の高さ10mから斜め正面へ向けます。駅裏・建物内部・地下を終点にしません。OrbitControlsの既定最短距離55mは近景を押し戻すため、近景フォーカス時は18m程度に下げる必要があります。移動する際は注視点とカメラ位置を両方反映してください。任意の出発点からの移動経路における建物回避は、この終点データの保証範囲外です。

`RAIL_VIEWPOINTS_ONLY=1 python3 scripts/rail-visuals-qa.py` でこの公開APIを読み込み、`focus-center.png` / `focus-dogenzaka.png` / `focus-miyashita.png` / `focus-sakuragaoka.png` を出力できます。

統合後の操作確認は `python3 scripts/rail-focus-qa.py`。2026-10-06、0.4の実UIで次の6項目が成功し、ブラウザ例外はありませんでした。

1. センター街の「沿線の様子を見る」をクリックし、カメラ座標・注視方向が公開APIと一致。
2. センター街から「街全体に戻る」をクリックし、元の俯瞰へ復帰。
3. 宮下東口の「沿線の様子を見る」をクリックし、カメラ座標・注視方向が公開APIと一致。
4. 東口近景で標準→軽量へ品質を変えてシーンを再生成しても、選んだ近景を保持。
5. 品質変更後の東口から「街全体に戻る」をクリックし、元の俯瞰へ復帰。
6. 設定画面から保存した全stateが、初期stateへ `applyAction(settings: quality=low)` だけを適用した期待値と完全一致。

移動は即時切替なので、補間中に建物を通過する経路は発生しません。

この操作テストでは街の `animate` コールバックだけを停止し、UI処理やPlaywrightの待機は通常どおり動作させています。写真はクリック後の実シーンを手動renderして取得し、カメラの上書きや画像後加工はしていません。実ファイルは [clicked-center.png](/workspace/shared/shibuya-artifacts/rail-focus/clicked-center.png)、[clicked-miyashita.png](/workspace/shared/shibuya-artifacts/rail-focus/clicked-miyashita.png)、[overview-restored.png](/workspace/shared/shibuya-artifacts/rail-focus/overview-restored.png)、[results.json](/workspace/shared/shibuya-artifacts/rail-focus/results.json) です。他の実景・模型の閲覧先は [画像と3Dの閲覧案内](visual-preview.md) にまとめています。

実測値は `Station_joint_development.userData` の `drawCalls / triangles / instances` で取得できます。これは追加グループのメインパス用描画バッチと三角形数で、影パスや画面外カリングを含む全画面の描画回数、FPS、GPU性能を示す数値ではありません。

2026-10-06、Chromium / SwiftShader で商業2地区・賃貸2地区を同時表示した実測:

| 状態 | 描画バッチ | 三角形 | インスタンス |
| --- | ---: | ---: | ---: |
| 完成・運営 | 16 | 5,176 | 438 |
| 完成・休止 | 15 | 5,176 | 438 |
| 工事中 | 12 | 3,320 | 280 |

週だけ変更した場合のグループ同一性、休止への切替、全計画を消したときの空状態を確認。交換時はジオメトリ2/2、マテリアル16/16、テクスチャ6/6の破棄イベントを確認しました。ブラウザ例外なし。統合シーンの西側全景、商業・賃貸の接写、東側、工事中、休止中の6枚を撮影し目視確認済みです。点字誘導線は中央柱を避け、工事看板は柱に文字が隠れない位置へ修正しました。

検証: Vite 起動後に `python3 scripts/rail-visuals-qa.py`。テスト用会社を実際の保存インポートUIから読み込み、統合済みシーンの商業・賃貸を撮影します。その後、同じ週状態の再利用・休止時再生成・リセット・全専有リソースの破棄を検証し、工事・休止状態を追加撮影します。合成資産の検証であり、通常プレイの到達時間や利益バランスの証明ではありません。出力先は `/workspace/shared/shibuya-artifacts/rail-visuals/` です。
